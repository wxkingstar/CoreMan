# 机器人记忆管理

AI 员工在工作目录中维护的记忆文件，可以由运行时节点上的 Agent 回收到管理台保存，也可以在管理台编辑后部署回节点。本文说明权限、同步规则与换机时的处理。

记忆正文只向机器人创建者和协作者开放；委员会或平台管理员身份不能旁路正文权限。编辑需要 If-Match，审计仅记录操作人与记录 ID，不记录内容。编辑和删除先存管理台，显式部署后才更新实例。删除清除正文并保留墓碑，自动回收不复活；重新编写是一项新的人工编辑。

`POST /api/infra/memories/collect` 接受实例专用 Bearer token，或有 memories scope 的签名客户端，须指定 server_id/port 等唯一实例目标。记忆 working_dir 必须精确匹配当前分配给该实例的唯一机器人。任一目录不匹配、校验值错误或文件越界，整个批次回滚。没有按目录名猜用户或跨实例映射。旧别名 `/api/robot/memories/collect|query|deploy` 保留；deploy 只部署库内当前快照，不接受任意文件输入。

每文件 256 KiB、每批 4 MiB/500 文件。mtime 超前超过 300 秒拒绝，hash 由服务端重算。相同内容只推进更新时间；库内更新时间更新则保留库内记录。生产运行应同步实例和服务器时钟。

管理接口为 `/api/admin/bots/{id}/memories`：列表/创建、单文件详情/编辑/删除、`collect`、`deploy`。列表不包含正文，已删除内容默认隐藏。恢复需重新填写正文。收集和部署是手动同步，可在机器人详情的记忆管理中操作。

新版 Agent 的 ping 返回 `memory_protocol=2`。部署前先验证能力，旧版不会收到写请求。协议 2 验证内容 hash/mtime，目标文件更新时拒绝覆盖，保留文件 mtime，支持墓碑删除。文件写入逐文件原子替换；多文件部署不是跨文件事务，IO 故障或其它进程同时改文件可能部分完成，应重新回收核对。CoreMan 在响应前复查 bot 和记忆版本，部署期间配置变化会提示冲突。网络超时不代表远端必然未写入。

工作目录必须与 Agent 可访问的真实运行路径一致，且落在其配置的 COREMAN_WORKSPACE_ROOT 下；不自动去掉家目录或猜测宿主机/chroot 映射。Agent 每小时自动上报默认开启，COREMAN_MEMORY_SYNC=0 可关闭。先升级服务端再升级 Agent；Agent 通过绑定身份分页取得当前分配的工作目录，只扫描这些目录，不扫描整个实例根目录。单机器人上限 500 文件/4 MiB（包括删除墓碑），超限拒绝，不截断后声称完整。

## 换机同步

管理台与限流卡片共用同一换机服务：原 Agent 提供 `read-memory`（只返回快照，不回调 CoreMan），服务验证目录/校验值后合并管理台记录，再向新实例协议 2 部署；确认完整后才提交改绑及会话清理。目标文件较新、旧 Agent 不支持快照、目标不支持协议 2 或网络失败时均不提交改绑。外部多文件写入仍可能部分完成，失败后需要核对目标文件；数据库事务不能回滚实例文件。

无已存记忆且原实例没有 Agent 配置时，保留旧版换机行为，结果标明 `not_configured`，不声称进行了回收；只有库内记忆时部署已有记录。存在运行中的任务时先等待或取消，技能安装在队列中也禁止换机。工作目录分配采用事务级锁，新建、改目录与换机不能抢占另一机器人目录。聊天和定时任务在构建请求时等待换机行锁，使用提交后的当前实例。

原 Agent 自动回收在本机锁内读取、锁外上报，避免 CoreMan 换机行锁与 Agent 操作锁相互等待。目标实例切换后，技能显示需要重新安装核验代码，旧审批约束与环境配置保留；不会把另一台实例当作已有相同安装包。

自动测试覆盖记忆同步的成功与失败路径、目录占用保护、限流换机、正常聊天、定时执行及 Agent 行为。跨机器的真实文件同步请在实际节点上验证。
