# 飞书接入与验证

CoreMan 使用企业自建应用。为同一企业部署：平台身份以 `user_id` 为键，不支持将不同企业中相同 user_id 当作不同员工。登录应用建议填写企业 tenant_key（平台应用的 corp_id 字段），登录返回的 tenant_key 必须匹配；跨企业部署应使用独立实例和数据库。

## 应用配置

在飞书应用中开启机器人能力并发布版本，配置可用范围。按实际使用功能申请消息接收、发消息、消息资源、CardKit 写入、通讯录及用户 user_id/邮箱/手机号权限。用户 user_id 权限是卡片归属与员工身份校验所必需，缺失时不能改用另一应用的 open_id 猜测身份。

事件订阅使用长连接：

- `im.message.receive_v1`
- `im.chat.member.bot.added_v1`
- `im.chat.access_event.bot_p2p_chat_entered_v1`
- 卡片回调 `card.action.trigger`

登录重定向地址为 `{PUBLIC_BASE_URL}/api/auth/feishu/callback`。管理台的平台应用启用对应能力，先完整同步通讯录再使用员工登录。通讯录同步先读取应用的授权范围，仅个人授权时直接获取该成员，不读取无权访问的根部门。需要 contact:contact.base:readonly（授权范围查询）、contact:user.base:readonly、contact:user.employee_id:readonly；部门范围还需相应部门读取权限。当前不支持基于用户组的通讯录范围，遇到此类范围会中止同步，避免误停用成员。邮箱与手机号若分别匹配不同账号，同步整体中止，需先处理冲突。

创建飞书机器人时填写应用凭证，一个应用只能绑定一个 CoreMan 机器人。需要人工求助回复时，通知/回调平台应用必须与唯一启用机器人的 app_id 一致。求助接收人引用当前通知回复；普通聊天不被求助流程截取。

机器人工作目录必须位于所选运行时节点的项目主目录之下，并允许节点运行用户读写。缺失目录时，Go 子进程启动错误可能表现为 `fork/exec .../claude: no such file or directory`；应同时核对工作目录和程序路径，不能只根据报错认定 CLI 缺失。

## 已实现的行为

网关父进程持有数据库租约，每应用一个子进程连接 SDK。入站数据库提交后才应答；超过两秒或失败要求平台重投。群聊只接受明确 @ 当前机器人的人类消息。进入聊天事件可以触发欢迎语，但不视作员工已发言或建立私聊可达关系。

卡片采用 JSON 2.0，流式 70ms/1 字符/fast，300ms 最小 API 调用间隔；九分钟转静态并继续更新同一卡片，不受旧 Agent 超时配置影响，接管沿用卡片与递增序号。连续失败六次或永久拒绝后，最终答案通过持久出站箱改用普通消息投递。长期卡片也转普通消息。出站永久失败留在管理台，未标成送达。消息 UUID 支持平台去重；平台的去重窗口与创建卡片后进程崩溃的窗口仍受外部接口约束，不承诺端到端恰好一次。

选择题复用公共逐题状态机，支持单选、多选与其他答案；提交后改为只读卡片。回调必须匹配实际发出的卡片消息、机器人、聊天与发起员工。没有将全部问题合并为一张表单。

图片和文件仅通过当前消息的官方资源接口下载，不接受外部 URL；大小上限 100 MB。飞书不做语音转写，明确提示暂不支持语音消息。长文本分片按 JSON 转义后字节数计量。通知应用发送限速与机器人流式发送分别留有余量。

## 验证范围

自动测试使用模拟平台、真实隔离 PostgreSQL 和 SDK 的真实事件分发器，覆盖提交前 ACK、超时重投、接管、序号、失败恢复、回调绑定、媒体路由、求助回复、登录和通讯录归并。

租户权限、卡片在客户端的显示、网络断线后的平台重投、资源下载及长连接接管，请在有授权的飞书测试应用中实际验证。网关健康检查通过不代表这些外部链路已经可用。飞书 SDK 1.7.3 会输出两条上游弃用警告，CoreMan 未屏蔽；升级 SDK 应单独评估。


## 定时任务通知设置

通知目的地在「定时任务 → 新建／编辑 → 通知设置」中配置，AI 员工编辑页只保留欢迎语。

- 私聊和群聊使用当前 AI 员工所属平台；飞书员工直接发飞书消息，无需 Webhook。接收人必须绑定相应平台身份。私聊未建立时，系统仅在存在唯一可用通知应用时尝试应用通知，否则展示失败原因。
- 群聊下拉展示该员工已收到过事件的群聊 ID，也可输入其它可达群聊 ID；选择记录不保证机器人当前仍在群内。
- 邮件继续使用平台配置的 SMTP。
- 「附加通知：企微群机器人」可用于跨平台同步。例如飞书员工向飞书群发送，同时同步到企微群。仅支持官方企微群机器人 HTTPS 地址，并且必须带非空 key。
- 新任务默认关闭企微群 Webhook。每个任务独立加密保存地址，页面只显示是否已配置。编辑时留空保留原地址；「移除已保存的地址」会关闭该渠道并在保存后清除地址。
- 保存后，在任务列表点击「发送测试通知」，向已保存的接收人发送固定测试消息，不运行 AI 任务。测试记录可刷新，待发送不代表已送达。正式运行的投递记录仍在执行记录中查看。
- 测试通知仅允许任务创建者发起；需要当前版本号。通知记录仅对有权操作该员工的用户开放，不返回 Webhook 或密文。

从通知 Webhook 仍配置在 AI 员工上的早期版本升级时，数据库迁移会把每个旧任务对应的员工 Webhook 复制为任务自己的加密地址，保持原开关；没有地址的任务关闭空开关。迁移需要原 MASTER_KEY，必须先完成数据库迁移再启动新版 API、调度器和 Worker。旧员工数据库字段保留用于兼容升级前已入队的任务，新任务不再继承它。


## 临时表情与思考过程

接管用户消息后，网关以当前机器人的身份添加 `Typing`（敲键盘）表情。
需要应用权限 `im:message.reactions:write_only`；缺少权限不会阻断正常回复。
只有首段可见正文成功送达后才移除表情，思考增量、空占位和新会话链接不触发移除。
结束、失败或取消后也会收尾；清理失败独立重试，状态持久化以支持网关接管。

思考区使用带文字标题的折叠面板，预览最近五个非空逻辑行（每行预览最多 240 字，客户端可能自动换行）。
飞书 Markdown / 折叠面板没有网页式固定高度滚动属性；完整内容通过原有受权限保护的会话页查看，
思考文本使用五行高度的滚动区域，向上阅读时不强制追随最新内容。该会话页继续只允许管理角色访问，
不会因为拥有卡片链接而扩大权限。没有底层会话链接时不显示入口。

CoreMan 不再只保留最后 200 字；Daemon 的 Claude 流式翻译器传递上游实际提供的思考增量、
工具参数及工具结果，Codex 传递其提供的 reasoning 文本及命令、文件修改、网页搜索、MCP 工具等执行详情。
上游未返回的推理不会补写。新过程日志写入 Daemon 会话记录，旧会话不回填。

发布需要先执行数据库迁移 `0025`，再更新服务镜像及运行时 Daemon 驱动。
旧驱动仍可工作，但不会产生本次新增的工具详情与过程日志。仅更新网关不能补齐旧驱动未发送的内容。

本轮验证：隔离 PostgreSQL 覆盖表情跨重启恢复、首段正文投递失败、清理重试和权限降级；
飞书测试应用实际接受 `Typing` 添加/删除、新思考面板及完整过程按钮。
示例正文更新成功后才调用删除表情接口，客户端已确认表情消失。

思考标题在尚未输出正文时每约 3 秒循环显示 `🤔 思考过程.`、`..`、`...`，
工具等待期间仍更新；正文开始或任务结束后恢复静态标题。标题单独局部更新，
不重置面板展开状态；标题更新失败不阻塞正文投递。
