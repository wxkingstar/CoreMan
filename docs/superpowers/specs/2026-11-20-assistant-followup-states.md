# 个人助理：跟进状态流转与所有者反馈

## 背景

事项总表上线后（见 `2026-11-18-personal-assistant-board-and-gaps.md`），所有者用下来有三点不顺：

1. **状态说不清。** 「在推进」是兜底组：不属于别的组就算在推进，模型其实没在跑。「卡在权限」单独一组，和「等你」「停滞」交叉。「我答应的」作为分类又在别处单独呈现。所有者看不出每组到底是什么意思、该做什么。
2. **「推后」不知道会发生什么。** 点了只让填日期，不能说为什么推、下次该怎么接着办。
3. **「办完」直接消失。** 没有说是怎么了结的，助理学不到东西。

所有者的要求：一条事项任何时候只处于一个明确的状态；每种状态都有一个所有者能反馈的入口，补充信息、改变助理的执行上下文；反馈要留存下来，通过下班编译进知识库。

## 五种状态

| 状态 | 判定（同时满足） | 显示 | 所有者能做的 |
|---|---|---|---|
| **等你**（owner） | 缺所有者的指示或信息，助理没法继续 | 拍板（决策、待批单）或补信息（「需要你：」一行） | 拍板、补充、改期、关闭 |
| **执行中**（working） | 此刻有子任务在跑或排队，或助理正在推进且最近有进展 | 正在做什么、多久前有进展 | 补充、改期、关闭 |
| **等别人**（others） | 已找了某个人，对方知道要提供什么 | 等谁、什么时候催 | 补充、改期、关闭 |
| **排期**（scheduled） | 现在做不了，有明确的启动日期 | 预计启动日期 | 补充、改期、关闭 |
| **停滞**（stalled） | 不在跑、不知道怎么办或该找谁、也没有要你批的 | 卡在哪（不知道怎么做 / 不知道找谁 / 反复失败 / 没人回 / 没进展） | 补充（给做法、指定人）、改期、关闭 |

「我答应的」不再单独成组，只是来源分类：现在能做的进执行中，做不了的进排期，不知道怎么办的进停滞，做到要所有者确认的进等你。「卡在权限」也不再单独成组，按缺口怎么开分到等你（所有者自己能开、能申请）、等别人（已申请，在等管理员）、停滞（要找管理员或没有办法）。

### 判定顺序（读取时推导，不落库）

1. 挂着未解决的缺口：已申请 → 等别人；所有者自己能开或能申请（authorize / credential / self_grant / request）→ 等你；其余（admin / node_admin / none）→ 停滞。
2. 挂着在途的审批单 → 等你（拍板）。
3. 所有者改过期、回看日还没到（`snoozed`）→ 排期。
4. decide → 等你（拍板）；needs_owner → 等你（补信息）；remind 到日子 → 等你（提醒）；handler=owner → 等你（你在办）。
5. 助理标了卡在哪（`stuck`）→ 停滞。
6. waiting 或同事在办 → 等别人；到了催办时间且已催满 2 次 → 停滞（没人回）。
7. 挂着的子任务在跑或排队 → 执行中；子任务卡住、失败 → 停滞。
8. 回看日在今天之后 → 排期。
9. 其余 → 执行中；2 个工作日没进展 → 停滞（没进展）。

### 等别人的催办

- 到催办时间：第一次按期限（`due_on` 已过），没有期限的 2 个工作日没进展；之后每次催办后再过 2 个工作日。
- 到点时平台交回助理一条「该催了」：助理起草催办消息、作为待批单提交并挂在这一条下（进入等你）；所有者批准发出后，助理用 `followup_progress` 带 `nudged=true` 记一句，催办次数加一、回到等别人。
- 催满 2 次还没回 → 停滞（没人回），由所有者界定。

### 停滞的界定

助理用 `followup_update` 的 `stuck` 标明卡在哪：`how`（不知道怎么做）、`who`（不知道找谁）、`failed`（反复失败）。所有者在页面上补充（给做法、指定人）后平台清掉 `stuck` 并立刻交回助理，助理据此改成执行中、等别人或排期；所有者也可以直接改期或关闭。

## 所有者的三个动作

- **补充**：任何状态都可以写一段话。平台把它以「[日期] 所有者补充：…」追加进备注，清掉 `stuck`，记一条反馈，并立刻交回助理（`owner_feedback`）重新判断。
- **改期**（替代「推后」）：选一个之后的日期，可以写备注。进入排期；备注追加进备注、记一条反馈，到日子交回助理时一起带上。
- **关闭**（替代「办完」与「不再需要」）：选原因——已当面沟通、已经解决、别人已处理、无需处理、其他，可以写一句。原因记在 `close_code`，同时记一条反馈。「无需处理」记为 dropped，其余记为 done。

## 反馈留存

新表 `assistant_feedback`：所有者在页面上的补充、改期备注、关闭原因各记一行（种类、原因代码、所有者原话；原话按所有者的数据密钥封存）。

- **当下**：补充与改期备注写进这一条的备注，助理下一轮就看得到。
- **长期**：下班编译的交代里列出窗口内的反馈（原话放在引用行），要求编译子任务把它提炼进知识库：对人的了解写进人物页，处理偏好写进 `profile/preferences.md`，「无需处理」说明这类事以后不必记，「已当面沟通」说明这件事或这个人习惯线下处理。

## 页面

- 五组顺序：等你、执行中、等别人、排期、停滞。每组标题旁有「?」，点开看这一组的定义、怎么进来的、你能做什么；顶部计数行旁有「状态说明」，一次看完五种状态和流转。
- 每条显示原因标签（为什么在这一组），以及补充、改期、关闭三个按钮。
- 缺口按上面的规则列在所在组里，操作不变。

## 不做

- 排期只到日期，不到时刻：交回助理沿用每日到期检查。
- 不改四个分类与现有工具的语义，只新增字段与参数。
