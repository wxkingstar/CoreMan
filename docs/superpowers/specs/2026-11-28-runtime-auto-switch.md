# 运行时全自动切换：额度用完时使用者无感

状态：方案第一版，方向与默认做法已确认，未实现
日期：2026-11-28
接续：[换运行时重新设计](2026-11-07-runtime-switch-redesign.md)。那一稿里没做完的部分（共享盘会话共享、跨后端摘要、跨存储增量）并入本稿，做法有调整的地方在 §8 列出。

## 1. 目标

运行时账号的额度用完时，不需要任何人操作，使用者的对话接着进行。使用者能感觉到的只有一次稍长的等待；只有换了另一种底座（模型变了）时才告诉他一句。

已定（2026-11-28）：

- 全自动切换，不再靠人点卡片或去管理台。
- 顺序：本机换席位 → 同底座换到别的机器 → 跨底座。跨底座有损，只在同底座没有余量时才用。
- 跨底座之后不自动换回。
- 跨存储切换时环境也跟着走。
- 换席位之后，所有显示账号和余量的地方一起变。

被本稿替换的旧决定：只由管理员手动切、撞限那一轮不自动续跑、不跨后端推荐、不做自动换席位、共享盘内会话共享先观察。

保持不变：环境变量只在平台后台配置，不随迁移；个人助理不自动换机（它换机不带目录内容），只跟着整机换席位；接续摘要用已定的便宜模型。

## 2. 现状

一个月的审计记录（只含成功的切换）：

- 换实例 99 次，每周约 20 次，涉及 23 个员工，最多的一个 14 次。
- 36 次同时换了模型（跨底座），这类只有文字续接。
- 46 次换了目录路径（跨存储），这类要搬文件、重装技能。
- 25 次来自撞限卡片，74 次是管理台或命令行手动切。

问题分四组，后面的设计逐条对应。

**撞限那一刻**

1. 只能事后发现：靠匹配回答里的英文告示识别，总要白跑一轮。
2. 撞限那条要人重发。只有业务系统发起的任务会排队自动重跑。
3. 推荐目标只看 7 天用量：不看 5 小时窗口，不排除同账号的实例，不跨底座。
4. 只有说话人是员工管理员才收到切换卡，其他人只看到额度表，没人被通知。
5. 定时任务、助理子任务、协作、任务会话不等额度：直接失败，或把告示当成结果。

**切换中**

6. 员工处于迁移隔离时，新消息入队但没有提示；同一人第二条消息会弹出「上一条还在排队」的忙碌卡，切完后等久了的还要再确认一次。
7. 等当前一轮没有上限，期间整个员工在所有会话里都不回复。
8. Claude 后台阶段的会话被直接关掉，不通知。
9. 回执只发到点卡片的那个会话；管理台发起的切换聊天里没有说明。

**切换后**

10. 来回切换丢上下文：文字续接只取上一个 relay 会话的记录，A → B → A 之后，第一次切换之前的内容全部丢失。
11. 跨底座只带最近 20 轮的问答原文，没有工具轨迹。
12. 同底座换机时会话文件经平台逐块搬，超过单会话上限或总时限就悄悄退回文字续接。
13. 回执和驱动提示与实际不符：无论是否降级都说「上下文已带过去」；Codex、OpenCode 续不上时即使带了续接文本也说「会话记录已不存在」。
14. 跨存储时依赖目录、开发模式的 worktree 不复制，MCP 授权要重做，预检不列。
15. 没有把一台机器上的员工批量迁走的入口。

**席位**

席位切换三种底座都支持：Claude（浏览器授权码）、Codex（设备码）、OpenCode（贴 API Key）。会话目录各席位共用，切换时在途的轮次留在旧驱动上跑完。显示上的问题：

16. 切换后节点返回的席位清单里，新当前席位的账号取的是切换前缓存的账号，要等下一次发现（约 60 秒）才更正。
17. 这段时间平台按旧账号做「同账号额度同步」，旧账号的余量可能被写到新席位上；新席位自己的额度要等下一次对话或每小时采集才更正，这期间账号和余量对不上。
18. 额度按实例加席位存快照：非当前席位显示的是上次切走时的数字，哪怕同一个账号在别的机器上刚上报过新值。
19. OpenCode 没有额度数据，只能在撞限后知道。

## 3. 总体结构

五个部分，各自独立可测：

| 部分 | 回答的问题 |
|---|---|
| 账号额度（§4） | 每个账号还剩多少、什么时候恢复 |
| 切换决策（§5） | 这个员工现在该换到哪 |
| 触发与续跑（§6） | 什么时候换、被打断的那条怎么接上 |
| 状态与环境跟着工作目录（§7） | 换过去之后上下文和环境是否完整 |
| 切换中的体验与管理（§9、§10） | 等待时看到什么、管理员看到什么 |

## 4. 额度按账号记

额度属于账号，不属于实例或席位。现在的存法（实例上的几列加每席位快照）是 16～18 的根源。

**数据**

新表 `runtime_accounts`，主键是底座加账号（邮箱小写；OpenCode 用服务商名）：

- 套餐类型。
- 5 小时、7 天两个窗口各自的用量、重置时间、观测时间。
- `exhausted_until`：已知用完时的恢复时间。来源有两个：窗口用量到 100% 且重置时间在未来；或一轮对话撞了限（从告示里解析出重置时间，解析不到就取已知窗口的重置时间，都没有就 30 分钟后再试）。
- 最近一次撞限时间。

席位仍由节点在心跳里上报，不另建表。平台用「节点 + 底座 + 席位 → 账号」找到额度。

实例上现有的额度列保留，改为当前席位账号的投影：账号行一更新，所有当前席位是这个账号的实例一起刷新。旧的每席位快照列不再写。

**写入**

- 每条额度上报带席位号。平台按上报席位的账号写账号行，不再要求它必须是当前席位。
- 撞限也是一次观测：写 `exhausted_until`。这样 OpenCode 和只有 7 天窗口的账号也有「已用完」状态。

**换席位**

- 节点在切换结果里直接返回新席位刚查到的账号和登录状态（切换前本来就查过一次登录），不再用缓存的旧值。修 16。
- 平台收到后在同一个事务里把实例的投影换成新账号的额度。没有快照交换，也没有按旧账号串写的窗口。修 17。

**备用席位的额度**

- Codex：按席位的环境读额度不消耗模型用量，对所有已登录席位每小时读一次。
- Claude：额度只随真实请求返回。备用席位平时不读；当它成为候选、并且它的账号在各节点都没有 30 分钟内的观测时，用它发一次最小请求（与现有健康检查同一种），拿到额度再决定。
- OpenCode：没有额度数据，只有 `exhausted_until`。

**显示**

所有地方都从「当前席位的账号」取数，换席位后一起变：

- 运行时管理的节点列表：账号、套餐、两个窗口。
- 席位弹框：每个席位显示它的账号当前的额度（不是切走时的快照），并标出观测时间。
- 换运行时弹框、命令行的节点与实例列表。
- 聊天里的额度表（自动切换开启后只在「都没有余量」时出现，见 §6.4）。

## 5. 切换决策

一个纯函数 `plan_switch(员工)`，输入是库里的状态，输出是按优先级排好的候选列表。自动切换、管理台的推荐、批量迁出都用它。

**余量判断**

- 可用：两个窗口都低于预警线（5 小时 90%、7 天 95%，沿用现值），且没有 `exhausted_until`。
- 紧张：过了预警线但没用完。只在同一层没有「可用」时才选。
- 用完：有未到期的 `exhausted_until`。不选。
- 不知道：没有观测。先按上一节读一次，读不到的不选。

**候选分层**

| 层 | 目标 | 要搬什么 |
|---|---|---|
| 1 | 本机同底座的另一个席位 | 什么都不搬，整机生效 |
| 2 | 同底座、同一份工作目录（共享盘上的另一台） | 只改绑定 |
| 3 | 同底座、另一份存储 | 增量同步文件与环境 |
| 4 | 另一种底座、同一份工作目录（含本机的另一种底座） | 只改绑定，接续摘要 |
| 5 | 另一种底座、另一份存储 | 增量同步，接续摘要 |

同一层内：先「可用」后「紧张」；再取两个窗口里较高的那个用量最低的；并列时取绑定员工数少的，避免都挤到一台。

候选还要满足：实例启用、节点在线且没在排空、已登录、最近健康检查没有失败、账号不是已知用完的；按员工创建人的身份过现有的可见性和团队策略；普通员工不进助理池。

**范围开关**

- 每个员工一个设置：自动切换「开」（默认）、「只换席位」、「关」。个人助理固定为「只换席位」。
- 全平台一个设置：「关」「只记录」「开」。上线先用「只记录」跑一段时间，对照记录看决策是否合理，再打开。

## 6. 触发与续跑

### 6.1 开轮前

任务被认领、准备开轮时，如果当前账号已知用完，不开这一轮：先按 §5 切换，再在新绑定上开轮。使用者看不到失败。这条路覆盖一台机器撞限后的其余员工和其余会话。

### 6.2 轮中撞限

一轮的结果是额度告示时：

1. 统一归类为「额度中断」，不算成功，也不作为回答发给任何人。聊天、定时任务、旁听、任务会话、协作都走这一处判断。修 5 里「把告示当结果」。
2. 给账号写 `exhausted_until`。
3. 这一轮的回复位置显示一行状态：「额度用完了，正在换一个运行时接着做」。不附额度表，不发切换卡。
4. 按 §5 切换，然后自动续跑（§6.3）。

不做「快到限额就提前换」：提前换会浪费剩余额度，而换席位之后只有第一个撞上的那一轮需要续跑。

### 6.3 被打断的那条自动续上

- 原生会话带得过去时（换席位、同底座）：在同一个会话里另开一轮，本轮说明写「上一轮因额度中断，接着把刚才的请求做完，已经完成的步骤不要重做」，后面是原消息。
- 跨底座时：新会话首轮带接续摘要（§7.3）和原消息。
- 结果接在原来的回复位置后面；平台不支持续写时另发一条。

风险：被打断的那一轮可能已经做了有外部影响的操作。原生续聊时模型看得到自己做过什么；跨底座靠摘要里的工具轨迹。经确认卡的业务系统写操作有现成的防重复，不受影响。

### 6.4 都没有余量

- 这条任务放回队列，`run_after` 取各候选账号里最早的恢复时间。把业务系统任务现有的等额度逻辑推广到所有任务类型。
- 每个会话只说一次：「各运行时的额度都用完了，预计 HH:MM 恢复后自动继续，不用重发」。
- 通知告警接收人一次，同一次事件不重复。
- 最长等 7 天，与业务系统任务一致。定时任务等到恢复后只补跑一次。

### 6.5 防抖与并发

- 同一个员工同一时刻只有一个切换作业（沿用现有的去重）。
- 同一台机器同一种底座的换席位用一把租约，第一个撞限的轮次触发，其余的等结果。
- 一条消息最多自动换 3 次，之后按 §6.4 等待。
- 任何一步失败：绑定不变，换下一个候选；全部失败按 §6.4 处理并告警。席位登录失效的标记为不可用。

## 7. 状态与环境跟着工作目录

记忆已经在 `<工作目录>/.coreman-memory/`。会话状态也放进工作目录，三样东西就只有一个去处，切换时不用分别处理。

### 7.1 会话状态镜像

目录：`<工作目录>/.coreman-state/<底座>/<relay 会话 id>/`。

- **每轮结束时**（成功、失败、撞限都算），驱动把这个会话的原生文件镜像过去：Claude 的对话记录与子代理记录，Codex 的 rollout 与 thread 绑定，OpenCode 的会话导出。文件是只追加的，按上次的偏移量只补新增部分。
- **每轮开始前**，本机没有这个会话的原生文件、或者比镜像旧时，先从镜像恢复，再原生续聊。
- 本机那份仍是工作副本。不在网络盘上实时写，sqlite 状态库留在本机，由 CLI 按会话文件自己补。

效果：

| 切换 | 现在 | 之后 |
|---|---|---|
| 换席位 | 不搬 | 不搬 |
| 同一份工作目录（共享盘、本机换底座） | 隔离、等空闲、逐块搬会话 | 只改绑定，不隔离，不等 |
| 另一份存储 | 文件与会话分两路搬，各有上限 | 状态随文件同步一起到 |

- 现有的会话搬运（导出、逐块读写）只留给未升级的节点。单会话 256MB 的上限不再导致降级。
- 镜像的清理跟平台会话的有效期一致。
- 默认的 `.gitignore` 加上这个目录。被员工自己删掉（例如 `git clean -x`）时，下一轮结束会从本机重新镜像。
- 个人助理不镜像（它的目录在沙箱里，现状不变）。

### 7.2 会话沿革

`chat_sessions` 增加沿革记录：这个会话键从上一次重置（清空或过期）以来用过的每个 relay 会话及其底座和起止时间。

- 文字续接和摘要按沿革取全部轮次，不再只取上一个 relay 会话。修 10。
- 换到一种底座时，如果沿革里有这个底座的原生会话且镜像还在：恢复它原生续聊，只把中间那一段作为本轮说明补上。来回切换时最初那一段不再丢。

### 7.3 跨底座的接续摘要

- 对 3 天内有对话的会话各生成一份。输入是沿革里的轮次，加上驱动每轮上报的精简工具轨迹（工具名、操作对象、成败，不含输出）。
- 固定结构：当前目标、已完成、进行中、下一步、关键约定、提到的文件。
- 切换时并行生成，单个 30 秒超时就退回最近 20 轮原文。
- 首轮注入，之后不再附。
- 跨底座后的第一条回复末尾加一句：「额度原因，已改用〈模型〉接着处理」。这是全流程里唯一主动告诉使用者的地方，因为模型确实变了。

### 7.4 跨存储：增量同步

- 目标节点保留上一次的副本作为基准。源节点出清单（路径、大小、修改时间，哈希有缓存），与目标的清单比对，只打包有变化的文件，目标删掉源已经没有的。
- 分两遍：第一遍员工照常工作，不隔离；第二遍隔离、等当前一轮结束、只补第一遍之后的变化。隔离时间只与第二遍的改动量有关。
- 传输沿用现有的整包通道：同一网络区直连，否则经平台中转。

### 7.5 跨存储：环境跟着走

| 内容 | 做法 |
|---|---|
| 依赖目录（`node_modules`、`.venv` 等） | 两端的系统、架构、工作目录绝对路径、解释器路径都相同时，随增量同步一起带走。否则不带，按下一行处理。 |
| 带不走的依赖 | 同步时记下依赖目录与对应的锁文件。绑定后由节点按锁文件重建（只做有锁文件的几种：npm、pnpm、uv、pip 的 requirements）。5 分钟内完成就在解除隔离前做完；超时转后台，首轮说明里告诉模型哪些还在装。没有锁文件的只在首轮说明里列出。 |
| 开发模式的 worktree | 纳入同步，目标上执行 `git worktree repair` 修正绝对路径。员工自己建的 worktree 同样处理。 |
| 技能 | 代码在工作目录里，随文件带走。不再把已安装的技能标记失败后重装；只有需要节点级安装步骤的才重跑。 |
| MCP 授权 | 换席位：同一台机器上把该员工技能用到的 MCP 凭据从旧席位复制到新席位。换机：经节点之间的加密通道导出导入，平台不落盘。凭据不能跨安装使用时（见 §11 V4），改为预检列出、首次用到时就地发起授权。 |
| 环境变量 | 已在平台后台，不涉及。 |

## 8. 与 11-07 稿的差别

| 11-07 稿 | 本稿 | 原因 |
|---|---|---|
| 共享盘新建 `state/`，各节点把原生会话目录软链过去 | 镜像放在各员工的工作目录里 | 不在网络盘上实时写；跨存储时自然跟着走；安全边界与工作目录相同，不新增「测试网络能读到线上对话」的范围 |
| 跨存储用 rsync 经受限 SSH | 清单比对 + 现有整包通道 | 效果相同（增量、以源为准），不用开 SSH 入口和签发一次性凭证 |
| 切换一律等当前这一轮 | 同一份目录的切换不等；跨存储只在第二遍等 | 同一份目录时两台节点可以同时为不同会话服务 |
| 节点上报存储域 | 沿用现有的共享探测 | 探测已经够用，少一个概念 |

## 9. 切换中的体验

- **换席位、同一份目录**：不隔离，使用者无感。在途的轮次留在原实例上跑完；撞限的按 §6.3 续上。
- **跨存储**：只在第二遍隔离。这期间每个会话的第一条新消息回一句「正在换运行时，大约 N 秒后自动处理」，N 取第二遍的估算。迁移造成的等待不弹忙碌卡，也不计入「等了多久要再确认」的时间。修 6、7。
- **后台阶段的会话**：算作在途。同一份目录时留在原实例上跑完；必须关掉时（跨存储且等待超时）发现有的停止通知，不再静默。修 8。
- **回执**：无损时不发。有损（跨底座）时按 §7.3 加一句。修 9、13。驱动在带了续接文本时不再输出「会话记录已不存在」。
- **切换卡**：自动切换打开后不再出现；全平台或该员工设为「关」时保留现在的卡片流程。

## 10. 管理台

- **自动切换记录**：时间、员工、原因、走的哪一层、耗时、是否有损、失败原因。
- **告警**：用了跨底座、所有候选都没余量、切换失败。
- **迁出全部员工**：节点上一个按钮，对上面每个员工跑一次 §5 并执行。维护机器时也用它。修 15。
- **预检**：显示属于哪一层、要同步的数据量、要重建的环境、要重新授权的 MCP、每个会话是原生续聊还是摘要。修 14。
- 手动切换保留。

## 13. 已确认的默认做法

下面几处已确认（2026-11-29）：

1. 跨底座后在第一条回复末尾告诉使用者一句（§7.3），其余情况完全不提示。
2. 不做「快到限额就提前换」（§6.2）。
3. 会话状态镜像放在工作目录里，员工自己读得到自己的会话记录（§7.1）。
4. 跨存储不再走 rsync，改为清单比对加现有通道（§7.4）。
5. 每个员工默认开启自动切换，个人助理只跟着换席位（§5）。
6. Claude 备用席位在成为候选时发一次最小请求来读额度，会消耗极少量用量（§4）。
7. 上线顺序：全平台先「只记录」，看一段时间再打开（§5）。
