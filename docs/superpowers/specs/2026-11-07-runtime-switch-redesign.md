# 换运行时重新设计：工作目录、上下文、记忆

状态：方案第二版，待评审
日期：2026-11-07

## 1. 一句话

把一个员工要带走的东西收敛成三样：**工作目录、上下文（3 天内有对话的会话）、记忆（跟着工作目录）**。

- 在同一块共享盘上：三样东西都已经在共享盘上。换机只是改绑定，秒级完成。
- 跨存储域（共享盘 ↔ 独立节点）：三样东西做一次增量同步。

切换到另一种后端（Claude ↔ Codex ↔ OpenCode）时，原生会话没法换格式。改为用便宜模型给 3 天内活跃的会话各生成一份接续摘要。

## 2. 用一个真实员工做样本

样本是一个运营类员工，代表「工作量大、换机频繁」的情况。数据于 2026-11-07 只读采集。

**工作目录（共享盘上）：4.1G，约 15 万个文件**

| 内容 | 大小 | 说明 |
|---|---|---|
| `outputs/` | 1.6G，4.3 万文件 | 员工生成的报表、模拟结果，含自带的 Python 依赖副本 |
| 3 个 Git 仓库 | 0.86G / 0.84G / 0.14G | `.git` 合计约 1.2G，远端在 GitHub，工作区都是干净的 |
| `reports/` | 0.6G，7.5 万文件 | — |
| `.worktrees/` | 0.12G | 员工自己建的 Git worktree，`.git` 文件里写的是绝对路径 |
| `.coreman-memory/` | 244K，28 条 | 库里也是 28 条，两边一致 |

**上下文：3 天内 10 个对话、262 轮**

- 对话来自 10 个群聊或私聊，加 1 个任务会话。最长的一个会话 100 轮。
- 节点上对应 8 个 Codex rollout，单个 0.2M～7.8M。同一员工所有历史 rollout 共 26 个、114MB。
- 单轮耗时中位数 29 秒，P90 153 秒，最长 13 分钟。

**换机频率：11 天换了 10 次**

- 多数是同为 Codex 的节点之间互换，原因是 Codex 席位额度用完。
- 最近一次（11-06）是共享盘内 Codex → Codex。源节点日志：`session-export failed: 会话文件超过迁移上限`。会话迁移是「全有或全无」，超限后**全部会话**改为文本续接。所以 100 轮的长会话，换机后只剩最近 20 轮的文字摘录。
- 同一节点更早一次：`workspace-export failed: 工作目录超过迁移上限（5 万个文件或 4G）`。这个员工**现在根本无法换到不在共享盘上的节点**（文件数是上限的 3 倍）。

**节点 HOME 里的状态（不在共享盘上）**

- `~/.codex` 3.5G：`sessions/` 2.1G，`thread_history_1.sqlite` 339MB，`state_5.sqlite` 等。
- `~/.claude` 505M。
- relay 会话目录 370M。

这说明：**工作目录和记忆已经共享，但上下文没有共享。** 共享盘内换机也要搬会话，一旦搬失败就丢上下文。这正是「切了之后上下文怎么处理不确定」的根源。

## 3. 现状 review（问题清单）

### 3.1 慢

1. **文件字节全部经平台中转，还要进出数据库。** 反向通道把请求和响应切成 48KB 的加密分块，写进 `runtime_chunks` 表（`coreman/core/runtime_nodes/transport.py`）。一个字节从源节点到目标节点要进出库 4 次。
2. **分块串行**，每块一次完整的反向调用（`workspace_transfer.transfer_chunks`）。
3. **节点只有一把全局锁。** `operations_lock`（`runtime_daemon/daemon.py:712`）让所有员工的文件操作、会话导出、技能安装都串行执行。
4. **每次全量**，没有增量。export 在锁里给所有文件算 sha256，哈希缓存超过 2 万条就清空。

### 3.2 切不动

1. `ensure_idle` 要求员工**完全空闲**，有任何对话、定时任务或技能安装在跑就 409。
2. 管理台是**同步 HTTP 请求**，最长 25 分钟（前端超时 30 分钟），中间断开就看不到结果。
3. 进程崩溃后员工停在 `migrating`，30 分钟内不回复。
4. 上限 5 万文件、4G；会话 500 个、5000 文件、512MB。超过任何一项就失败，或者整体退回文本续接。
5. 前置条件分散在十几个能力位里，半路才暴露。

### 3.3 上下文和记忆不确定

1. 原生会话状态在各节点自己的 HOME 下，共享盘内换机也要搬，而且搬的过程是「全有或全无」。
2. Codex 和 OpenCode 的「relay 会话 → 原生会话」映射只存在 relay 会话目录里，闲置 72 小时被清理（`pkg/sessions/store.go`）。
3. 跨后端只有最近 20 轮「用户原话 + 最终回复」，工具调用和中间结论全部丢失。
4. 记忆先回收、再复制文件、最后部署，中间写入的记忆可能丢失。共享盘上这一套回收和部署其实多余。

## 4. 新设计

### 4.1 存储域

每个节点上报自己所在的**存储域**（`storage_domain`）：

- 挂共享盘的节点，上报共享文件系统的标识，加上挂载根目录。
- 独立节点上报自己的节点 id。

平台据此判断两台节点是否在同一个域。这个上报代替每次换机都要做的 `workspace-probe` 探测。探测保留为校验手段：域相同但探测不通过时，拒绝换机并报警。

### 4.2 共享盘上的目录布局：三样东西都放上去

```
<共享盘>/
  workspace/<员工>/                  工作目录（现状）
    .coreman-memory/                 记忆（现状，跟着工作目录）
  state/                             新增：运行时状态
    relay-sessions/<provider>/<sid>/ relay 会话目录：映射、附件、续接文本
    claude-projects/                 各节点 ~/.claude/projects 软链到这里
    codex-sessions/                  各节点 $CODEX_HOME/sessions 软链到这里
    opencode-exports/<sid>.json      OpenCode 会话每轮结束导出一份
```

各后端的处理方式：

- **Claude**：会话 jsonl 存在 `projects/<工作目录路径换成->/`。所有共享盘节点的挂载路径都是 `/home/coreman/workspace`，所以目录名在每台节点上都一样。把 `~/.claude/projects` 整体软链到共享盘后，任何节点都能直接 `--resume`，不用搬。多席位的 projects 已经软链回默认席位，所以对席位同样适用。
- **Codex**：rollout 是只追加的 jsonl，可以放在共享盘上。`state_5.sqlite`、`thread_history_1.sqlite` 这类 sqlite 不能放 NFS，继续留在本机。按现有代码注释，Codex 会凭 rollout 自己补上本机状态库，但新出现的 `thread_history_1.sqlite` 要实测（见 §7 V1）。如果实测不行，退回「每轮结束把 rollout 增量镜像到共享盘，目标节点续聊前回灌到本机」。
- **OpenCode**：会话在 sqlite 里，不能共享。驱动每轮结束执行一次 `opencode export`，写到 `opencode-exports/`。目标节点续聊前发现本机没有这个会话，就先 `import`（导出导入已实测可保留会话 id）。
- **relay 会话目录**放上共享盘，映射就不会因为节点不同而丢失。72 小时清理继续由驱动执行，与平台会话 TTL 一致。

同一会话不会被两台节点同时写：平台保证员工同一时刻只绑定一个实例，切换时先等当前这一轮结束（§4.4）。NFSv3 的锁只在本机生效（`local_lock=all`），但这里只有一个写入方，不受影响。

### 4.3 四种切换

| | 同后端 | 跨后端 |
|---|---|---|
| **同存储域**（共享盘内） | ① 只改绑定，原生续聊 | ② 改绑定 + 接续摘要 |
| **跨存储域**（共享盘 ↔ 独立节点） | ③ 增量同步 + 原生续聊 | ④ 增量同步 + 接续摘要 |

样本员工 11 天 10 次切换，大多数属于 ①。

**① 同域同后端：一步到位**

- 等当前这一轮结束（§4.4）。
- 改 `relay_server_id`，会话键全部原样保留。
- 不复制文件，不回收、不部署记忆，不重装技能，也不搬会话。
- 目标节点下一轮直接续聊同一个原生会话。
- 预计耗时：等当前轮结束的时间 + 1 秒。

**② 同域跨后端**

在 ① 的基础上，对 3 天内有对话的会话各生成一份接续摘要（§4.5），作为新后端新会话的首轮背景。记忆不用动，三种后端读的是同一个 `.coreman-memory/`。技能代码都在工作目录里，不重装。

**③④ 跨存储域**

- 工作目录、`.coreman-memory/`、本员工 3 天内活跃会话的状态文件，三样一起做增量同步（§4.6）。
- ③ 原生续聊；④ 用接续摘要。
- 预计耗时：第一次同步与目录大小成正比；之后来回切换，只与这期间的改动量成正比。

### 4.4 不要求空闲，只等当前这一轮

- 点击切换后，员工打上「切换中」标记：新消息照常入队但不认领，用户收到一句「正在切换运行时，稍后继续」。
- 已经在跑的对话或定时任务：**默认等它跑完**（已定）。管理员可以手动打断。
- 排队中、从未认领过的任务（含技能安装）不阻塞切换，切换后在新实例上执行。
- 切换改为后台作业：管理台和限流卡片只创建作业，然后显示进度。作业有租约，进程崩溃后由别的实例接着做，或者回到原绑定，不再有 30 分钟的停摆。

### 4.5 接续摘要

**哪些情况需要生成**

- 跨后端切换（② ④），针对 3 天内有对话、并且对话轮数 ≥ 3 的会话。轮数少于 3 的会话，直接附原文。
- 同后端切换后原生续聊意外失败（驱动报会话不存在），对这一个会话按需补生成。
- 同后端、原生会话还在（① ③）：**不生成**。

样本员工如果做一次跨后端切换，需要为约 10 个会话生成摘要。

**怎么生成**

- 模型用 DeepSeek V4.1 Flash（已定），平台侧调用，需要配置对应的 API Key。
- 输入：这个会话 3 天内的 `chat_logs`，包括用户原话、最终回复，以及驱动新上报的精简工具轨迹（工具名、操作的文件路径或命令前几十个字、成败，不含输出正文）。
- 输出固定结构：当前目标、已完成、进行中、下一步、关键决定与约定、提到的文件。
- 在等当前这一轮结束的同时，各会话并行生成。单个超时 30 秒就退回「最近 20 轮原文」，不卡住切换。
- 首轮注入内容：摘要、最近几轮原文、一句「同一位员工、同一个工作目录，以上是之前的进展」。之后的轮次不再附。

### 4.6 跨存储域：切换时 rsync

**只在切换时拷贝，平时不同步（已定，2026-11-07）。** 只有用户在切换运行时选了「云上节点 ↔ 独立节点」，这次切换作业才执行一次 rsync。员工平时在哪个域工作，数据就只在那个域。没有后台同步，也没有常驻的同步任务。

**怎么连**：云上节点在私有网络里，独立节点（如 Mac mini）在办公网络的 NAT 后面，云上连不进去。所以 rsync 命令一律在**独立节点上执行**，经 SSH 连到一台云上共享盘节点：

- 云上 → Mac mini：Mac mini 执行 rsync，从云端拉取。
- Mac mini → 云上：Mac mini 执行 rsync，推送到云端。

这只决定哪一端执行命令，不是主动同步：命令只在切换作业里、由平台下发时才执行一次。

细节：

- 云上那台节点作为入口，开放一个只能访问共享盘员工目录的受限 SSH 账号（rrsync 限定目录）。凭证由平台在每次切换时签发，用完即作废。
- rsync 自带增量和断点续传。15 万个文件的清单比对只要几秒。第一次切过去是全量，之后只传改动。
- 平台只下发「哪个员工、哪个方向、一次性凭证」并等待完成，不再碰文件字节。经平台和数据库中转的旧路径只留给未升级的节点。
- 先等当前这一轮跑完（§4.4），再执行 rsync，以源为准（`--delete`）。执行期间员工的新消息排队。

**同步什么**

- 工作目录，排除 `node_modules`、`.venv`、`__pycache__`、缓存目录和 `.env*`（环境变量一律在 CoreMan 后台配置，已定）。
- `.coreman-memory/` 随目录同步，不再单独回收和部署。同步完成后平台回收一次作为备份。
- 本员工 3 天内活跃会话的状态：relay 会话目录、Claude jsonl、Codex rollout、OpenCode 导出文件。
**为什么要保留对面的旧副本（上一版的「回退点」，改个说法）**

员工从独立节点切回云上后，独立节点上那份目录不删，作为**下次切换时 rsync 的增量基准**：下次再切过去，只传这期间的改动，不用再传 4G。旧副本只能被同步覆盖，平台不会把它当成数据来源。占用的空间由节点磁盘告警兜底，不另设保留期。

**路径差异**

独立节点的主目录不同（例如 `/Users/<用户>/workspace`）。同步后要修正：

- Claude 会话目录名需要按新路径重命名。
- Git worktree 的 `.git` 文件和仓库里 `worktrees/*/gitdir` 记录的是绝对路径，需要按新路径改写。
- Codex rollout 里记录的 cwd 不同，能否续聊要实测（§7 V3），不行就按 ④ 处理。

### 4.7 记忆

- 位置不变：`<工作目录>/.coreman-memory/`，三种后端共用。
- 同域切换：什么都不做，只校验目标节点读得到。
- 跨域切换：随目录同步。平台库只作为备份、管理台编辑和审计的数据源，继续每小时回收一次。
- 去掉换机流程里的「回收 → 部署」，消除中间写入丢失的窗口。

### 4.8 前置检查一次列全

点「切换」之前，预检直接给出：

- 属于四类中的哪一类。
- 目标实例是否登录、额度如何。
- 跨域时预计要同步的数据量和耗时。
- 需要在目标重新授权的 MCP、需要重装的技能（只在跨域时）。

能力位合并成一个 `switch_protocol` 版本号，旧节点直接提示「请先升级」。

## 5. Mac mini 能不能直接挂共享盘

**不建议用来做工作目录。** 原因：

1. **网络**：现在用的极速型 NAS 只能在云上私有网络内挂载。Mac mini 要挂，必须先打通 VPN 或专线到 NAS 所在地域的私有网络。
2. **延迟**：Mac mini 在美国西海岸办公室，NAS 在东海岸，往返约 60～70ms（推断），是同可用区（约 0.3ms）的 200 倍。NFSv3 的每次元数据操作（stat、open、readdir）都是一次往返，属性缓存过期后要重新确认。样本员工的仓库有几万个文件，一次 `git status` 冷启动粗算要几十秒到几分钟，现在是秒级。Agent 常用的 `rg`、`find`、`npm`/`pip` 安装（大量小文件）都会成倍变慢。顺序读写大文件反而影响不大。
3. **可用性**：挂载用的是 `hard`，VPN 一断，访问工作目录的进程会全部挂起，节点表现为卡死。线上已经有过节点内存卡死的教训，这类问题很难排查。
4. **安全**：共享盘里有所有员工的目录，Mac mini 所在的办公网络就成了能读到线上员工数据的入口。

**已定（2026-11-07）**：Mac mini 不挂共享盘，工作目录和会话记录都不挂。Mac mini 作为独立存储域，与云上节点之间切换时，按 §4.6 **直接拷贝文件**。拷贝是增量的：第一次全量，之后只传改动。共享盘内部的切换按 §4.3 ① ② 一步到位。

## 6. 分期

**第一期：共享盘内一步到位。** 覆盖样本员工的大多数切换。

1. 节点上报 `storage_domain`；同域切换走 ①：只改绑定，跳过文件、记忆、技能和会话的搬运。
2. 共享盘上新建 `state/`，各节点完成 Claude projects、Codex sessions、relay 会话目录的软链迁移（先合并各节点已有内容，同名以较新者为准）。
3. 切换改为后台作业；等当前轮结束代替 `ensure_idle`；作业租约与自动回退。
4. 预检一次列全。

第一期进度（2026-11-07）：

- **3 已完成。**
  - 管理台换实例或目录时，`POST switch-relay?background=true` 返回 202 和 task_id，由 worker 执行；进度和结论在 `GET switch-jobs/{id}` 查看，排队中或等待中可以取消。
  - 限流卡片走同一个作业，改到普通车道。
  - 作业先隔离员工、再等手上这一轮结束，排队的消息切换后在新实例上处理。
  - 作业中途断掉时，由 reaper 解除隔离，绑定保持不变。
  - 不带 `background` 的旧调用方（CLI）行为不变。
- **4 部分完成。** 预检补充了「将等待的进行中任务」和目标实例的健康状态。
- **额外修复：会话迁移改为按会话限额。** 单个会话最多 256MB / 1000 个文件，超过的只跳过这一个，并在平台日志里记录；以前是整次导出失败，所有会话都退回文本续接。样本员工那次就是被一个 774MB 的 rollout 拖垮的。
- **1、2 未开始。**
  - 第 2 项要先完成 §7 的 V1、V2 实测。
  - 第 1 项在共享盘布局落地之前，沿用现有的 `workspace-probe` 判断是否共享。

- **过渡：整包传输（2026-11-14）。** 在 rsync 落地之前，两端都报 `workspace_pack` 时，复制改为源节点把清单里的文件打成一个 gzip tar，按 2MB 分块经平台中转，目标节点核对大小和哈希后只按清单解开。调用次数从每个文件至少一读一写降到每 2MB 一读一写，文件多的目录从几分钟降到几秒。字节仍经过平台和数据库，也没有增量；第三期 rsync 照旧。

**第二期：跨后端接续摘要。**

5. 驱动上报精简工具轨迹。
6. DeepSeek V4.1 Flash 并行生成接续摘要，带超时回退。
7. OpenCode 每轮导出到共享盘，目标节点按需导入。

**第三期：独立节点。**
