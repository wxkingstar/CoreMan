# 飞书群聊读文档

## 背景

「连接飞书」得到的个人授权只在本人私聊（和本人的私有定时任务）里挂载，群聊一律不挂，
防止群成员或注入文本借发起人的身份读别的文档再转述到群里。代价是群里发文档链接让 AI 员工
看时，它一份也读不到：应用身份此前没有任何云文档权限。

## 原则

群里能拿到的，只有本群本来就能看的内容；超出部分须由发链接的人本人逐篇同意。

## 两层

### A 层：应用身份读群可见文档（默认）

机器人以飞书应用自身（tenant_access_token）读取，并先证明文档对本群可见，满足其一：

1. 文档协作者里有本群（`member_type=openchat`、`member_id` 是本群 chat_id）；
2. 链接分享为「组织内获得链接的人可阅读/编辑」，且本群不是外部群；
3. 链接分享为「互联网上获得链接的任何人可阅读/编辑」。

证明不了就不读。只靠「应用读得到」不够：应用读得到的文档包括共享给它所在**其他**群的文档、
以及被单独添加为文档应用的文档，直接读会把别处的文档泄到本群。

知识库链接先解析节点：可见性按节点（`type=wiki`）查，正文按节点下的实际文档读。
「本群是知识空间成员」这种继承来的可见性第一期不认，走 B 层。

### B 层：发链接的人逐篇放行

A 层读不到、且本轮提问人已连接飞书时，AI 员工可以发起放行：系统在群里发一张固定格式的
卡片（@ 提问人），列出要读的链接，说明群里其他人不一定有权限查看。按钮是回复按钮，只有
提问人能点，点了就是他发给机器人的下一句话：

- 「仅本次读取」：本群、本人、这篇文档放行 1 小时，期间这个人在本群提问时，AI 员工可以以
  他的身份只读这篇文档；
- 「共享给本群并读取」：以本人身份把本群加为文档的「可阅读」协作者，之后走 A 层；同时视为
  「仅本次读取」，应用仍读不到时用本人身份读。只有档位允许代为分享（「全部权限，可代发消息」）
  才显示；
- 「不用了」：拒绝。

约束：

- 只能对本轮提问人消息里（含引用的消息）出现的链接发起，AI 员工不能自己拼文档；
- 放行绑定机器人、群、本人、文档 token，别人提问时不生效，过期失效；
- 只读：B 层不挂授权、搜索、写入、发送类工具；
- 旁听插话、调度回合、机器人之间求助、定时任务都不挂这组工具。

## 接口

新 MCP 服务 `coreman_feishu_docs`（`/api/runtime/feishu-docs/mcp`），只在飞书群聊、
运行时声明 `feishu_group_docs_v1` 的回合挂载。工具只收链接，不收裸 token：

| 工具 | 作用 |
|------|------|
| `feishu_doc_read` | 读文档正文（docx、知识库里的 docx）；表格、多维表格返回子表/数据表清单 |
| `feishu_doc_sheet_read` | 读电子表格区域 |
| `feishu_doc_base_records` | 查多维表格记录 |
| `feishu_doc_request_access` | 请提问人放行（B 层） |

能力凭证绑定任务、群和会话（relay session），服务端每次调用都重新核对：任务仍在跑、来源事件
是本群里真人发来的消息、会话没被重置。

## 数据

`feishu_doc_consents`：一次放行请求，状态 pending → approved / declined / expired。
卡片消息 ID 从出站记录取，点击按卡片消息 ID 与按钮文字对上请求。保留 30 天。

## 待真机验证

- 文档共享给群后，群里的机器人应用能否读到（官方 FAQ 写了文件夹分享给群可行）；
- 应用作为（经群获得的）阅读者，能否调用协作者列表与公共设置接口；
- 知识库节点的协作者列表是否包含经群获得的权限。
