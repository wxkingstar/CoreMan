AI 员工的文件、备份与换机

日常操作围绕“查看文件、备份、切换运行时”展开。文件在运行时电脑上，平台负责操作入口、权限与迁移进度。

2026-09-16 · 基于当前仓库代码核查

01 · 工作目录旁直接查看文件

工作目录

/home/ai/finance-assistant/ 查看文件

界面示意，按钮不连接真实运行时
  • 员工详情页及编辑页，在路径后放“查看文件”。打开大侧栏：左侧目录树，右侧文件预览或编辑，底部固定“保存”。
  • 支持文本和 Markdown 查看、编辑；图片预览，其他格式提供下载。大文件不直接载入编辑器，显示大小并提供下载。
  • 保存前校验文件版本；文件被 AI 或其他人修改时展示冲突，保留用户草稿，禁止静默覆盖。关闭未保存编辑时提醒。
  • 新建尚未完成时显示“创建后可查看”；离线时明确显示“运行时离线”。移动端采用目录与内容分屏切换。

权限与员工管理绑定；文件访问限定该员工目录，拦截路径穿越和指向目录外的链接。运行中的任务可能修改文件，首次实现对执行中的员工暂时禁用编辑与备份，查看仍可使用。

02 · 用“备份到 Git”表达提交和推送

文件侧栏提供“Git 备份”页：仓库地址、分支、凭证选择、连接测试、上次成功备份时间与待备份文件。

选择变更文件 → 填写备注（可自动生成） → 备份到 Git

只有远端推送成功才显示“已备份”；仅本地提交成功显示“待上传”，允许重试。

  • 地址与分支按员工保存，凭证加密保存并复用现有凭证设施；不能依赖用户在运行时手工登录 gh/glab。
  • 已有仓库核对远端配置，不静默改写 origin。支持空远端首次提交；本期使用已存在的远端仓库，不自动创建托管平台仓库。
  • 备份默认排除密钥、环境变量、运行缓存和依赖目录；展示实际文件清单及排除原因。AGENTS.md 和 CLAUDE.md 链接均纳入备份。
  • 分支冲突、受保护分支或认证失败时给出明确状态，不强制推送。记忆仍由专用回收/部署流程负责，不依赖 Git。

03 · 切换前，先把工作目录准备好

选择新运行时后，自动检查在线状态、可用空间、路径权限、目标目录归属与 Git 可用性，再显示可用方式。

方式适用情况用户需要知道
从当前运行时复制
默认推荐		旧运行时在线，希望保留最新工作文件包含未提交文件；复制清单与排除项可查看，不受 Git 上次备份时间限制
从 Git 恢复已配置远端仓库，可读取对应分支恢复远端版本；展示备份时间/提交，旧机器未推送的变化不会包含在内
使用目标已有目录目录确属该员工且检查通过需要明确选择复用；不把其他员工或未知目录直接覆盖
  • 新安装默认根目录 /home/ai/，员工目录为 /home/ai/<员工标识>/。无权限时明确提示选择可写根目录；现有节点保持实际配置，不擅自迁移老目录。
  • 目标不存在时，按选定方式创建；目标非空且归属不明时，建议新目录。禁止将复制内容直接混入已有文件。
  • 复制通过平台协调的受鉴权分块传输完成，不要求两台运行时能直接 SSH 互通。先写临时目录，校验文件清单和哈希后再落位。
  • 复制保留业务文件和目录内安全链接。Git 元数据采用受控重建，保留业务文件的未提交变化，避免搬运旧机器的 hook、凭证与绝对路径配置；实际排除清单提前展示。

04 · 新员工自动准备工作说明

创建时生成 AGENTS.md，包含员工身份、职责、工作目录约定和记忆使用说明，不写入凭证。再创建相对软链接：

CLAUDE.md → AGENTS.md

两种 AI 工具读取同一份说明，编辑任一入口都落到 AGENTS.md。

  • 目录准备完成之前保持“初始化中”，不接收执行任务。未选运行时时可保存为“待分配”，首次绑定时初始化。
  • 已有 AGENTS.md 时保留内容；仅有 CLAUDE.md 时保留原文并迁为主文件；两份内容不一致时提供差异和合并入口，不自动覆盖。
  • 修正现有工作区准备逻辑对 AGENTS.md 的 Git 排除规则；链接检查允许上述目录内链接，拒绝目录外链接。
  • 初始化失败可重试，不能出现页面显示可工作而实际目录不存在的情况。

05 · 文件与记忆一起迁移，最后切换

暂停新任务等待执行结束回收最新记忆准备目标文件部署并校验记忆更新运行时绑定恢复接单
  • 迁移状态覆盖排队、定时任务及自动换机入口，阻止检查后又派入新任务；同一员工只能有一个迁移操作。
  • 旧运行时在线时强制回收最新记忆，独立持久化快照后再部署。数据库中的删除标记一并迁移，避免旧记忆复活。
  • 旧运行时离线时，复制不可用；Git 恢复可以继续准备，但使用平台最后记忆快照必须展示时间并由用户明确选择“使用上次记忆继续”。没有快照则说明记忆不可恢复，不默认继续。
  • 目标文件、说明文件和记忆均校验通过才更新绑定；失败保留旧绑定、旧目录与已回收快照，展示可重试步骤。数据库提交失败时不开放目标接单。
  • 迁移完成后旧目录保留，不自动清理。同一节点只切换 AI 类型时复用原目录，仍检查说明文件兼容性。
  • 聊天历史在平台保留；原运行时会话不承诺可直接续接。现有技能在切换后要求重装，界面显示状态，不能把“文件已复制”当作技能已验证可用。

方案取舍与实施边界

方案收益 / 限制
只用 Git 迁移实现简单，但丢失未推送文件，也无法替代记忆迁移，不满足完整需求
文件管理 + Git 备份 + 迁移编排（推荐）满足五项需求，复用已有运行时通道和记忆协议；需要增加文件操作与持久化迁移状态
统一共享磁盘减少复制，但需要所有运行时挂载同一存储，增加部署要求，暂不采用
