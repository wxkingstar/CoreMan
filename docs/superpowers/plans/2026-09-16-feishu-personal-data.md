# Feishu private personal data implementation plan

> Use subagent-driven-development for independent runtime and UI work; primary implements authorization and reads with TDD.

Goal: A verified Feishu human in a private bot conversation can authorize and read their messages and meeting artifacts on the server. Group, WeCom, scheduled, delegated, anonymous and stale tasks fail closed.

Architecture: New durable encrypted grants per (bot,user), OAuth device flow against the bot's own app, identity checked against the original verified inbound open_id/user_id/tenant. A dedicated task-scoped MCP endpoint exposes only typed read tools and authorization start/status/revoke. No arbitrary path proxy, no user credential sent to Runtime. Browser page can list/revoke only own grants using interactive session auth. Official OAuth/API HTTP requests are mocked only at external boundaries in tests.

Global constraints: use current source of truth InboundEvent and active Task, not request-supplied chat_type/user; never fall back to app/creator identity; every call rechecks enabled bot, user, allowlist, grant app fingerprint. Group must never receive personal tools or reuse personal sessions. Task credentials scrubbed from static/inherited env, expired and redacted. Read outputs are external data, never instructions. No external sends. Persist grants across container restarts; encrypt tokens and pending codes with row-specific AAD. Keep existing dirty root work untouched.

1. Auth/store/policy + migration 0029: failing tests for denied provenance, identity mismatch, durable refresh/revoke. Implement models and narrow client. Scope locking serializes refresh, revocation and use.
2. Read tools + MCP: search messages, messages by IDs, chat history, meeting search/detail, minutes search/detail, note and document read. Pydantic extra-forbid schemas, limits, pagination indicators, generic upstream errors. Verify group and forged capability denied before HTTP, no write tools, no token leak.
3. Worker/runtime: inject COREMAN_FEISHU_PERSONAL_URL/TOKEN for verified single Feishu human chats with a connected grant or a valid pending authorization; explicit connection commands remain supported. After consent the agent decides when to read, with no per-message prefix. Revocation removes automatic access. Require current Runtime restricted capability. Claude uses only personal MCP, no built-in tools/hooks/shared memory/session persistence; Codex and old Runtime fail closed. Use fresh session and replace shared bot prompt/env. Redact credentials. Tests per backend and stale env.
4. Own-authorization UI: GET /api/me/feishu-authorizations returns {items:[{bot_id,bot_name,status,scopes,expires_at}]}; DELETE /api/me/feishu-authorizations/{bot_id} revokes own grant. Add page, navigation, 3 locales and component tests. Connection starts in bot private chat to bind verified origin, not admin role.
5. Privacy review: inspect log/session/memory paths, ensure private retrieval cannot populate group context or self-service infra endpoints. Add regression tests for bypasses. Docs clearly cover scopes, private-only behavior, cancellation, release/runtime requirements.
6. Verify targeted + full backend, frontend, Go; independent security/code review; integrate scoped change to current branch without disturbing dirty files and deploy using established guarded flow if feasible.
