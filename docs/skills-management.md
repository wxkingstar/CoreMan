# 技能管理

技能是从 Git 仓库中的插件清单同步到目录、再安装到 AI 员工工作目录的能力包。本文说明技能来源与目录、环境预设、审批与安装任务，以及卸载的边界。

目录同步读取 marketplace.json 的 plugins[].source 与插件 plugin.json 的名称、描述、版本，不执行清单内的指令。新条目默认停用；同步描述与版本不自动改安全等级、预设、审批策略或启用状态。插件常见结构为 `./plugins/{name}/.claude-plugin/plugin.json`。

public 技能由机器人管理员安装；internal 技能须先获委员会审批。审批绑定具体目录 revision（包版本另存 version），批准数据库范围须是申请子集。目录发生变化的待批申请需重新提交。安装通过持久任务经反向通道调用机器人所属的运行时节点，失败显示原因，不把入队视作安装成功。

环境预设加密，管理响应脱敏，不覆盖机器人已有键。用户提供的技能配置只允许目录声明的字段。请求级身份、系统授权和 bot_token 保留键不能来自预设。

安全提示词是模型约束，不是数据库访问控制。底层数据库账号必须对应被批准的实际权限，未知计量或权限不能用默认全开代替。编辑 bot 原提示词时应重建已批准技能的合并提示词，卸载须清除该技能的安全提示词；工作区代码的实际删除沿用人工仓库管理。

## 已接通的安装链

管理 API：`/api/admin/skill-sources`、`/skills`、`/env-presets`；目录对成员只显示已启用项，来源/预设/目录写入限 AI 委员会和平台管理员。机器人自己的 `/bots/{id}/skills` 与安装/卸载只允许创建者和机器人管理员；全局角色不旁路。委员会 `/skill-approvals` 批准或拒绝申请，审批和写入均校验版本。

安装任务绑定技能 revision、来源 version、实例和工作目录、申请人、触发人及审批。执行前后重新检查；安装中取消或卸载不会被迟到响应恢复为“已安装”。worker 失联只标记待核查失败，不自动重放安装。内部安装的 Task.user_id 是实际点击批准的人，另行检查申请人仍有机器人管理权。

凭据实现采用独立的 BotSkill.effective_env_enc 加密层：安装成功后保存预设及用户输入快照，正常对话与定时任务每次合并有效技能配置，机器人手工配置优先。不同技能对同名变量给出不同值时拒绝安装。卸载立即从后续请求中排除该层，不删除手工配置。预设修改不会悄悄改变已安装技能的凭据，需重新安装。失败的重新安装保留上次成功安装的安全约束与配置。编辑基础提示词保留已批准安全约束。

卸载不是远端代码销毁或外部凭据吊销：已运行的请求、安装进程、工作区 Git 代码和 MCP 本地文件不会由管理台强行删除；MCP 配置中已有的静态凭据仍须由对应服务撤销。管理台仅撤回后续 CoreMan 注入的技能环境层。此边界在管理说明与操作提示中明示，不能将“已卸载”当作外部账号已撤权。

目录维护：先登记来源，再执行 `coreman skills sync <marketplace-git-url> --source <key>`。清单限定 500 插件、每文件 256 KiB，拒绝越界路径、名称冲突；不会执行插件指令。Git 克隆禁用模板、全局配置、凭据助手、HTTP 重定向和 file/ext 协议，180 秒超时，临时仓库自动清理。来源地址必须与登记值一致；新条目默认停用，更新只修改描述和包版本，整个数据库同步一笔事务。

管理台已增加技能目录/来源/预设、机器人安装面板与审批页，支持按数据库范围提交、显示待审批和安装状态、失败原因与版本冲突。MCP 明文配置不会读回；编辑留空表示保留加密原值。预设以掩码保留原值，未知掩码拒绝写入。

Agent 执行安装器与探针时移除全部 COREMAN_ 环境变量，避免子进程继承管理服务身份。实际运行用户仍须限制主机文件和外部账号权限；此过滤不等于操作系统沙箱。


## 管理台来源与环境编辑

技能来源是技能的归属和默认 Git 安装仓库。添加来源只登记地址；在来源列表点击「同步到目录」调用 `POST /api/admin/skill-sources/{id}/sync`，读取仓库清单并导入目录。该接口仅允许委员会和平台管理员，要求 `If-Match`，远端读取结束后再次检查操作者权限及来源版本，审计记录归属实际操作者。读取或解析失败不会部分导入，错误不回显 Git 输出。服务端须已安装 Git，并具备私有仓库的读取权限；管理台不会代配 SSH 密钥。来源列表显示关联技能数量，可直接跳转到按该来源筛选的目录。同步不会安装技能，也不会自动启用新条目。

技能新建面板分为基本信息、安装配置、授权与环境、用户配置四组；显示最终使用的仓库地址，数据库专用选项折叠在高级配置中。默认安全约束仍是可选模板，内部技能安装申请时必须明确安全约束。保存与目录启用均不触发安装。

环境预设支持键值对与 `.env` 文本双向切换，保存时直接校验当前编辑区。文本支持注释、`export`、单/双引号、多行引号值及双引号中的换行转义；含 `#` 的值需加引号。不执行命令、不展开变量。变量名沿用平台的大写命名规则；重复键、格式错误和未闭合引号会显示行号并阻止保存与模式切换。已有密钥仅返回掩码，两种模式都可保留掩码来保持原值。文本注释与排版不存入预设，切换为键值对后只保留变量数据。

环境预设保存时要求掩码与该变量当前原值的完整掩码一致。仍含圆点但被删改、拼接或移到其他变量的掩码会被拒绝，避免将残缺掩码写成实际值；前端提供相同提示。更新密钥需填写完整的新值。


## 私有 GitLab 来源的 Project Access Token

来源的添加/编辑面板支持独立的 Project Access Token。后端仅返回 `has_access_token`，原值使用 `skill_sources.access_token_enc` 加密保存，不回显也不写入审计内容。编辑留空保留原 token，勾选移除才清除；更换仓库时必须重新填写或移除 token。认证时将 `git@host:group/project.git` 转为同一项目的 HTTPS 地址，临时 Git 配置仅为该仓库附加认证头，禁用重定向及凭据助手，不把 token 放入 URL、命令参数或 Git 配置文件。

GitLab 私有仓库要求 token 具备 `read_repository` 且项目角色至少为 Reporter；只有 `read_api` 和 Guest 无法拉取代码。同步会针对 Git 403 和认证失败返回固定的可操作提示，不回显远端输出。

安装任务仅向同一来源仓库传递 token，独立仓库覆盖地址不匹配时拒绝安装。运行时节点先用 token 克隆到临时目录，再对本地副本执行技能安装，安装器不接收 token。来源目录同步直接由管理服务完成，不依赖运行时节点更新。
