# 技能管理

技能是从 Git 仓库中的插件清单同步到目录、再安装到 AI 员工工作目录的能力包。本文说明技能来源与目录、环境预设、审批与安装任务，以及卸载的边界。

目录同步读取 marketplace.json 的 plugins[].source 与插件 plugin.json 的名称、描述、版本，不执行清单内的指令。新条目默认停用；同步描述与版本不自动改安全等级、预设、审批策略或启用状态。插件常见结构为 `./plugins/{name}/.claude-plugin/plugin.json`。声明了 MCP 服务的插件登记为 MCP 技能，见下文「仓库中的 MCP 技能」。

Git 技能安装后以工作目录中的 `.agents/skills/<技能名>` 为唯一副本，Runtime 自动建立 `.claude/skills/<技能名>` 的相对软链接，供 Claude Code 读取。重复安装复用正确链接；同名真实目录、错误链接或工作区外的目标会报错并保留原文件。只有确认 `SKILL.md` 存在并完成链接后才报告安装成功。已有节点须升级 Runtime，已有技能重新执行安装后补齐链接。MCP 安装写入工作目录的 `.mcp.json`，Claude Code 直接读取，Codex 由驱动每轮转换后挂载。

public 技能由机器人管理员安装；internal 技能须先获委员会审批。审批绑定具体目录 revision（包版本另存 version），批准数据库范围须是申请子集。目录发生变化的待批申请需重新提交。安装通过持久任务经反向通道调用机器人所属的运行时节点，失败显示原因，不把入队视作安装成功。

环境预设加密，管理响应脱敏，不覆盖机器人已有键。用户提供的技能配置只允许目录声明的字段。请求级身份、系统授权和 bot_token 保留键不能来自预设。

安全提示词是模型约束，不是数据库访问控制。底层数据库账号必须对应被批准的实际权限，未知计量或权限不能用默认全开代替。编辑 bot 原提示词时应重建已批准技能的合并提示词，卸载须清除该技能的安全提示词；工作区代码的实际删除沿用人工仓库管理。

## 已接通的安装链

管理 API：`/api/admin/skill-sources`、`/skills`、`/env-presets`；目录对成员只显示已启用项，来源/预设/目录写入限 AI 委员会和平台管理员。机器人自己的 `/bots/{id}/skills` 与安装/卸载只允许创建者和机器人管理员；全局角色不旁路。委员会 `/skill-approvals` 批准或拒绝申请，审批和写入均校验版本。

安装任务绑定技能 revision、来源 version、实例和工作目录、申请人、触发人及审批。执行前后重新检查；安装中取消或卸载不会被迟到响应恢复为“已安装”。worker 失联只标记待核查失败，不自动重放安装。内部安装的 Task.user_id 是实际点击批准的人，另行检查申请人仍有机器人管理权。

凭据实现采用独立的 BotSkill.effective_env_enc 加密层：安装成功后保存预设及用户输入快照，正常对话与定时任务每次合并有效技能配置，机器人手工配置优先。不同技能对同名变量给出不同值时拒绝安装。卸载立即从后续请求中排除该层，不删除手工配置。预设修改不会悄悄改变已安装技能的凭据，需重新安装。失败的重新安装保留上次成功安装的安全约束与配置。编辑基础提示词保留已批准安全约束。

卸载不是远端代码销毁或外部凭据吊销：已运行的请求、安装进程、工作区 Git 代码和 MCP 本地文件不会由管理台强行删除；MCP 配置中已有的静态凭据仍须由对应服务撤销。管理台仅撤回后续 CoreMan 注入的技能环境层。此边界在管理说明与操作提示中明示，不能将“已卸载”当作外部账号已撤权。

目录维护：先登记来源，再执行 `coreman skills sync <marketplace-git-url> --source <key>`。清单限定 500 插件、每文件 256 KiB，拒绝越界路径、名称冲突；不会执行插件指令。Git 克隆禁用模板、全局配置、凭据助手、HTTP 重定向和 file/ext 协议，180 秒超时，临时仓库自动清理。来源地址必须与登记值一致；新条目默认停用，更新只修改描述和包版本，整个数据库同步一笔事务。

管理台已增加技能目录/来源/预设、机器人安装面板与审批页，支持按数据库范围提交、显示待审批和安装状态、失败原因与版本冲突。MCP 明文配置不会读回；编辑留空表示保留加密原值。预设以掩码保留原值，未知掩码拒绝写入。

Agent 执行安装器与探针时移除全部 COREMAN_ 环境变量，避免子进程继承管理服务身份。实际运行用户仍须限制主机文件和外部账号权限；此过滤不等于操作系统沙箱。


## 管理台来源与环境编辑

技能来源是技能的归属和默认 Git 安装仓库。添加来源只登记地址；在来源列表点击「同步到目录」调用 `POST /api/admin/skill-sources/{id}/sync`，读取仓库清单并导入目录。该接口仅允许委员会和平台管理员，要求 `If-Match`，远端读取结束后再次检查操作者权限及来源版本，审计记录归属实际操作者。读取或解析失败不会部分导入，错误不回显 Git 输出。服务端须已安装 Git，并具备私有仓库的读取权限；管理台不会代配 SSH 密钥。来源列表显示关联技能数量，可直接跳转到按该来源筛选的目录。同步不会安装技能，也不会自动启用新条目。

技能新建面板分为基本信息、安装配置、授权与环境、用户配置四组；显示最终使用的仓库地址，数据库专用选项折叠在高级配置中。默认安全约束是可选模板；内部技能的申请与批准也不强制填写安全约束（技能自身已做约束时可留空），留空时不向提示词追加内容，数据库范围仍须选择。保存与目录启用均不触发安装。

环境预设支持键值对与 `.env` 文本双向切换，保存时直接校验当前编辑区。文本支持注释、`export`、单/双引号、多行引号值及双引号中的换行转义；含 `#` 的值需加引号。不执行命令、不展开变量。变量名沿用平台的大写命名规则；重复键、格式错误和未闭合引号会显示行号并阻止保存与模式切换。已有密钥仅返回掩码，两种模式都可保留掩码来保持原值。文本注释与排版不存入预设，切换为键值对后只保留变量数据。

环境预设保存时要求掩码与该变量当前原值的完整掩码一致。仍含圆点但被删改、拼接或移到其他变量的掩码会被拒绝，避免将残缺掩码写成实际值；前端提供相同提示。更新密钥需填写完整的新值。


## 仓库中的 MCP 技能

同一个技能仓库可以同时放 Git 技能和 MCP 服务，同步后都出现在技能目录里，AI 员工按同样的流程安装、审批和配置环境变量。插件沿用 Claude Code 的插件格式声明 MCP，任选一种：

- plugin.json 的 `mcpServers` 写对象：`{"name": "figma", "mcpServers": {"figma": {...}}}`；
- plugin.json 的 `mcpServers` 写插件目录内的相对路径，文件内容为 `{"mcpServers": {...}}`；
- 不写 `mcpServers`，在插件目录放 `.mcp.json`。

插件目录里有 `SKILL.md` 时仍按 Git 技能处理，MCP 声明不导入，已有的技能插件不受影响。一个插件只能声明一个服务，安装时以插件名作为服务名写入员工工作目录的 `.mcp.json`，原服务名不使用。配置检查与管理台手工登记相同：`stdio` 须有 `command`，`http`、`sse` 须是不含用户信息的 HTTPS 地址，`env` 只能是字符串且变量名受平台规则约束。配置不合法时整次同步失败，不会部分导入。

```json
{"mcpServers": {"figma": {"command": "npx", "args": ["-y", "figma-developer-mcp", "--stdio"], "env": {"FIGMA_API_KEY": "${FIGMA_API_KEY}"}}}}
```

同步以仓库为准：插件新增或去掉 MCP 声明时，目录条目在 Git 与 MCP 两种安装方式之间切换；MCP 配置有变化时覆盖目录里保存的加密配置，管理台对这类条目的手工修改会在下次同步时被覆盖。已安装的员工要点「升级」或重新安装，才会把新配置写入工作目录。密钥不要写进仓库：在技能的「用户需填写的配置」或环境预设里声明变量（如 `FIGMA_API_KEY`），配置里用 `${变量名}` 引用。

运行时两种后端都会加载 `.mcp.json`：

- Claude Code 自己读取，`${变量名}` 由 Claude 展开，stdio 服务继承员工的环境变量。
- Codex 由驱动每轮把每个服务转成 `-c mcp_servers.skill_<名字>={...}`；名字带 `skill_` 前缀，避免和节点全局配置里的同名服务合并出错。stdio 服务通过 `env_vars` 拿到员工的环境变量（`COREMAN_` 开头的除外），`env` 中的明文值经进程环境传入，不出现在命令行。http 服务的 `Authorization: Bearer ${变量}` 转为 `bearer_token_env_var`，`${变量}` 形式的请求头转为 `env_http_headers`。Codex 不支持 SSE；command、args、url 中的 `${...}`、`env` 中引用其他变量名（如 `"A": "${B}"`）也无法转换。这些服务在 Codex 下跳过，并在节点日志中记录，本轮其余功能照常。

## 需要 OAuth 登录的 MCP 技能

有的远程 MCP 服务只能 OAuth 登录，不收静态令牌，例如 Figma 官方 MCP（`https://mcp.figma.com/mcp`）。这类服务往往只放行登记过的客户端：Figma 的动态客户端注册对 CoreMan 返回 403，但接受 Codex 和 Claude Code。所以授权交给 AI 员工所在实例上的 CLI 完成，令牌留在该 CLI 自己的凭据存储里（Codex 在节点的 `~/.codex/.credentials.json` 或系统钥匙串，Claude Code 在它的凭据存储），CoreMan 不保存令牌。

**标记**：技能的「需要 OAuth 授权」（`skills.mcp_oauth`）只能用于 http/sse 服务。仓库同步时，没有 `headers` 的远程服务自动标记，带请求头的不标记，以仓库为准。

**按员工命名**：两个 CLI 的令牌都按服务名存放。标记了 OAuth 的技能安装时以 `<技能名>-<员工 ID 前 8 位>` 写入 `.mcp.json`，并删掉同名的旧条目。同一节点上的员工各用各的授权，Codex 下挂载为 `skill_<技能名>-<员工 ID 前 8 位>`。没有标记的 MCP 技能仍用技能名。

**授权流程**（员工的技能列表，限创建者和员工管理员）：

1. 点「授权」，`POST /api/admin/bots/{bot}/skills/{skill}/mcp-login`。平台先 `ping` 确认节点支持（`mcp_oauth: 1`），再让员工所在实例执行 `codex mcp login skill_<名字> --no-browser`（Claude Code 先把同名同配置的服务登记到项目的 local 作用域，再 `claude mcp login <名字> --no-browser`）。CLI 在 pty 里运行，打印授权链接，并在本机回环端口等待回调。平台返回授权链接和会话 ID，链接 10 分钟有效。
2. 用户在浏览器打开链接，登录要使用的账号并允许访问。浏览器随后跳到 `http://127.0.0.1:<端口>/…` 或 `http://localhost:<端口>/…`，页面打不开是正常的。
3. 用户把地址栏里的完整地址粘贴回管理台，`POST …/mcp-login/complete`。节点只接受本次会话的回环地址：主机、端口、路径和 `state` 都要一致。它把查询串送到 CLI 的回环端口，由 CLI 换取并保存令牌，以 CLI 的退出码判定成败。成功后在 `bot_skills` 记下授权人、时间和实例（`mcp_authorized_*`），审计记为 `skill.mcp_authorized`。授权码不进审计和日志。
4. 「撤销授权」`DELETE …/mcp-login` 让 CLI 注销令牌，审计记为 `skill.mcp_revoked`。Linux 上没有系统钥匙串时，Codex 默认模式的注销会失败，节点会改用文件存储模式重试。

**边界**

- 授权的账号由这个 AI 员工使用，所有与它对话的人都以该账号的权限访问。
- 令牌在实例上：员工换到别的节点或换了 AI 类型，列表会显示「需重新授权」。
- 令牌由 CLI 自己刷新。刷新失败（被撤销或过期太久）时，工具调用会报认证错误，需要重新授权。
- 停用技能不会注销 CLI 里的令牌，要先撤销授权再停用。
- 节点要升级到带 `mcp-login-*` 操作的版本；旧节点会提示升级。已安装的技能在节点升级后要点「升级」或重新安装，才会换成按员工命名的服务名。

## 从目录删除技能

技能目录的操作列提供「删除」，调用 `DELETE /api/admin/skills/{id}`，仅限委员会和平台管理员，要求 `If-Match` 为当前 revision。仍有 AI 员工安装着该技能（含安装中、安装未完成）或有待审申请时拒绝删除（409），并列出这些员工；须先在员工的技能中停用 / 撤回。

删除只在 `skills.deleted_at` 留墓碑，不删行：目录、员工的可安装列表和已停用的安装记录都不再显示它，安装申请返回 404；安装与审批历史保留，审批页仍显示技能名。来源再次同步时跳过已删除的同名条目，结果里的 `skipped` 即跳过数量，不会重新导入。需要恢复时在目录中用同名新建技能：复用原来那一行并按本次提交重新配置，删除前的 MCP 加密配置不会带回，审计记为 `skill.restore`。删除记为 `skill.delete`。

## 本地安装与环境变量导出

成员没有技能仓库的权限，也能把技能装到自己的电脑。技能目录的操作列提供「本地安装」，任何登录用户都能看到已启用的 Git 技能的安装命令：

```bash
curl -fsSL https://coreman.example.com/api/skill-install/<令牌> | sh
```

在项目根目录执行：技能装到 `.agents/skills/<技能名>`，再建相对软链 `.claude/skills/<技能名>` → `../../.agents/skills/<技能名>`，Claude Code 从软链读取。在用户主目录执行则对所有项目生效。重复执行即更新：先解压到同级临时目录，确认有 `SKILL.md` 后再替换旧目录。`.claude/skills/<技能名>` 已是真实目录或指向别处的软链时报错退出，不覆盖。脚本只依赖 `sh`、`curl`、`tar`，支持 macOS 与 Linux。

**下载链路**：`POST /api/admin/skills/{id}/local-install` 生成命令。令牌用主密钥加密，绑定本人和技能，30 分钟内有效、可重复执行，访问日志里打码。`GET /api/skill-install/{令牌}` 返回安装脚本，`GET …/archive` 返回技能压缩包；两者凭令牌访问，不需要登录态，每次都重新检查账号仍启用、技能仍启用且是 Git 技能。服务端按员工安装同样的规则取仓库（独立仓库地址优先，来源令牌只用于来源自己的仓库），浅克隆后找 `SKILL.md` 中 `name` 与技能名一致的目录（不分大小写，同名取最浅的），只打包这个目录，不含 `.git`，文件总大小上限 50 MB。下载记审计 `skill.local_install`。克隆失败只返回固定提示，不回显 Git 输出。

**环境变量导出**：同一弹窗里，平台管理员还能看到「环境变量」。选好数据库与数据源后点「查看明文」，`POST /api/admin/skills/{id}/env-exports` 按员工安装的规则合并固定预设和所选数据库（Doris 数据源取 `_doris` 组），拼成 `export` 语句，值原样以明文返回；不同环境组给同名变量不同值时拒绝（409）。「用户需填写的配置」写成注释，由使用者自行填写。每次查看记审计 `skill.env_export`，只记环境组，不记取值。

两个管理接口都要求本人在管理台交互登录，AI 员工借成员身份的 `bot_token` 不能调用。MCP 技能不提供本地安装。


## 私有 GitLab 来源的 Project Access Token

来源的添加/编辑面板支持独立的 Project Access Token。后端仅返回 `has_access_token`，原值使用 `skill_sources.access_token_enc` 加密保存，不回显也不写入审计内容。编辑留空保留原 token，勾选移除才清除；更换仓库时必须重新填写或移除 token。认证时将 `git@host:group/project.git` 转为同一项目的 HTTPS 地址，临时 Git 配置仅为该仓库附加认证头，禁用重定向及凭据助手，不把 token 放入 URL、命令参数或 Git 配置文件。

GitLab 私有仓库要求 token 具备 `read_repository` 且项目角色至少为 Reporter；只有 `read_api` 和 Guest 无法拉取代码。同步会针对 Git 403 和认证失败返回固定的可操作提示，不回显远端输出。

### Git 用户名

令牌随 HTTPS Basic 认证发送，用户名默认是 `oauth2`，这是 GitLab 的约定（GitLab 不校验用户名）。有的服务要求用户名是令牌所属的账号，例如阿里云云效 Codeup 要填令牌所属的云效账号名，用 `oauth2` 会返回 401。这类来源在编辑面板的「Git 用户名」里填写账号名；留空仍用 `oauth2`。用户名不是机密，明文保存在 `skill_sources.git_username`，同步目录和安装技能都使用它。服务器拒绝令牌时，Git 可能报 `could not read Username`（终端提示已关闭），同步和安装都会把它识别为认证失败，提示检查 token 与用户名。

安装任务仅向同一来源仓库传递 token，独立仓库覆盖地址不匹配时拒绝安装。运行时节点先用 token 克隆到临时目录，再对本地副本执行技能安装，安装器不接收 token。来源目录同步直接由管理服务完成，不依赖运行时节点更新。
