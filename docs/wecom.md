# 企业微信接入与验证

CoreMan 与企业微信的对接分为两部分，彼此独立配置：

| 部分 | 企业微信侧 | CoreMan 中的位置 | 是否必需 |
|---|---|---|---|
| AI 员工的聊天入口 | 智能机器人（API 模式、长连接） | 「AI 员工」→ 扫码创建或平台凭证 | 使用企业微信聊天时必需 |
| 平台应用 | 企业自建应用 | 「平台应用」 | 可选：登录、通讯录同步、应用通知、求助回复回调 |

按单一企业部署：员工身份以企业微信 `userid` 为键，不支持把不同企业中相同的 userid 当作不同员工；跨企业应使用独立的 CoreMan 实例和数据库。

## 一、AI 员工使用的智能机器人

### 企业微信侧准备

扫码创建（见下文）时企业微信会直接建好机器人，可以跳过这一步。手动填写凭证时，按企业微信官方《智能机器人开发 → 开发前必读》：

1. 在企业微信管理后台进入「工作台 → 智能机器人」新建机器人。
2. 在机器人编辑页切换为 **API 模式**，连接方式选择 **长连接**。CoreMan 只使用长连接，不使用 URL 回调方式，因此不需要机器人的 Token / EncodingAESKey。
3. 在机器人详情页复制 `BotID` 与 `Secret`，妥善保管。

长连接由 CoreMan 的企业微信网关（`gateway-wecom`）主动连到 `wss://openws.work.weixin.qq.com`，部署环境只需能出站访问该地址，不需要为机器人开放公网入站端口。新建员工时 API 服务也会连一次该地址校验凭证，扫码创建还需要 API 服务与 scheduler 能出站访问 `https://work.weixin.qq.com`。企业微信规定同一机器人同一时刻只允许一个有效连接：不要让其他程序或另一套 CoreMan 使用同一组凭证，否则双方会互相顶替。

### 在 CoreMan 中创建 AI 员工

前提：已在「运行时管理」接入至少一个在线的运行时节点（见 [Runtime Daemon](../runtime_daemon/README.md)），节点上的 Claude Code 或 Codex CLI 已登录。

在「AI 员工」中新建，在「更多设置」中把平台切换为「企业微信」。

#### 扫码创建智能机器人（默认）

「平台设置」中的「扫码创建企业微信机器人」开启时（默认开启），平台切到企业微信后不用填写凭证，保存按钮变为「扫码创建企业微信机器人」：

1. 先按真实创建流程校验员工配置（标识、团队、运行时、模型、工作目录），不落库；校验不通过不会出二维码，避免企业微信侧留下用不上的机器人。
2. 服务端向企业微信申请扫码会话，管理台只把二维码画给发起人本人。二维码内容本身就能取回机器人的 Secret，所以请本人扫码，不要截图或转发；页面也不提供可转发的链接，别人的扫码会话一律按不存在处理。
3. 发起人在企业微信中确认后，服务端取回 BotID 与 Secret 并立即删除本地保存的 scode，再用长连接订阅（`aibot_subscribe`）校验一次后马上断开，交给网关接管。Secret 只加密保存在服务端（最长 24 小时），浏览器只拿到 BotID；随后由同一次操作创建员工并一次性消费凭证。
4. 发起人关掉页面也不影响取回：scheduler 每 3 秒替他查一次，服务重启后从数据库接着查；关窗口时服务端还会最后查一次。取回后还没关联员工的机器人，本人下次新建企微员工时可以直接复用，不必重复扫码。
5. 企业微信不会告知扫码会话过期，CoreMan 按 5 分钟自行计时；网络错误时退避重试，但不会超出有效期。每人同一时间只保留一个二维码，每小时最多发起 10 次。

注意事项：

- 这条通道依赖企业微信命令行工具使用的未公开接口（`work.weixin.qq.com/ai/qc/*`），没有文档，也没有稳定性保证，适合企业内部使用，不宜作为对外产品唯一的开通方式。接口返回无法识别的结构时，日志记 `wecom_provision_unexpected_response`，告警渠道会收到对应告警。此时可在「平台设置」关闭「扫码创建企业微信机器人」，新建企微员工改为手动填写凭证；已经扫码建好、尚未使用的机器人不受这个开关影响。
- 实测扫码成功后，企业微信仍允许用同一个 scode 反复取回 Secret，CoreMan 无法让它失效。二维码若可能被别人看到或拍下，请到企业微信管理后台重置该机器人的 Secret，再在 CoreMan 中编辑该员工更新凭证。
- 实测扫码建出的机器人默认已开启 API 模式长连接，长连接订阅校验可以直接通过。
- 每个机器人仍需一位成员用企业微信扫码确认，不能无人值守地批量创建。机器人的名称、头像以企业微信中的设置为准，可在企业微信管理后台修改。
- 校验提示企业微信拒绝订阅时，到企业微信管理后台确认该机器人为「API 模式」、连接方式为长连接，然后在弹窗中点「重新校验并创建员工」，不必重新扫码。
- 手机上确认创建之后会出现「确认授权」：**AI 员工机器人不需要，直接返回即可**。点了会把创建者本人的全部企业微信数据能力（待办、日程、会议、文档、邮件、微盘、通讯录）授给这个机器人，拿到它凭证的人就能以创建者的身份读写企业微信。成员要让 AI 员工以自己的身份办事，走下文「连接企业微信」的个人绑定，不需要这里的授权。
- 扫码建出的机器人默认「仅个人使用」，其他同事发不进消息。建好后请在电脑端企业微信「工作台 → 智能机器人 → 该机器人 → 使用模式」改为「多人使用」并选择可使用成员（企业微信没有开放修改接口，只能手动改一次）。
- 检查已有 AI 员工机器人是否带着创建者的数据权限：在 API 容器里运行 `python -m coreman.cli wecom-bots audit`（只读）。输出里 `data_access: true` 的机器人，请创建者在电脑端企业微信的「可使用权限」中取消授权。
- 指标 `coreman_wecom_provision_total{stage, result}` 覆盖二维码生成（`generate`）、结果查询（`query`）、会话结局（`session`：`succeeded` / `expired` / `cancelled`）与凭证校验（`verify`），可据此计算生成成功率、扫码完成率、超时率与校验失败率。

#### 手动填写凭证

使用已有机器人，或关闭了扫码创建时，在「更多设置」中打开「手动填写凭证」（关闭扫码创建后直接显示凭证输入框）：

| 表单字段 | 填写内容 |
|---|---|
| AI 员工标识 | 小写字母、数字、下划线或连字符，2–50 位，以字母或数字开头；创建后不可修改，即 `bot_key` |
| 平台凭证 → AI 员工 ID | 智能机器人的 `BotID`（必填） |
| 平台凭证 → 密钥 | 智能机器人的 `Secret`（必填） |
| 运行时 / 模型 | 选择在线的运行时实例及其有效模型 |
| 工作目录 | 绝对路径，必须位于所选运行时节点的项目主目录之下（不能等于项目主目录本身、不能含 `..`），同一节点上一个目录只归一个 AI 员工 |
| 使用白名单 | 留空表示不限制；非空时只有名单内、且身份能识别的员工可以使用 |

工作目录需要预先在运行时节点上创建，并允许节点的运行用户读写。CoreMan 与 Runtime Daemon 都不会自动创建该目录。

手动填写的凭证与扫码取回的凭证走同一套校验：保存前 CoreMan 连一次长连接订阅，企业微信返回成功才保存。企业微信同一机器人只允许一个连接，若这组凭证正被其他程序使用，那条连接会被断开一次。编辑已有员工的凭证时不做这项校验，免得把正在服务的连接踢下线。

保存并启用后，网关会在几秒内认领该机器人并建立长连接。在「运行状态」中查看该机器人的连接状态：`已订阅` 表示连接与凭证均正常。

### 行为说明

- 单聊消息直接处理；群聊中企业微信只在消息 @ 机器人时回调，CoreMan 把群消息一律视为提到了机器人。
- 支持文本、图片、文件、语音、视频、图文混排及引用消息；其他消息类型会被忽略并记录 `wecom_msgtype_unsupported`。
- 用户进入单聊会话时可发送 AI 员工配置的欢迎语。
- 回复以流式消息推送。企业微信要求单条流式消息在 10 分钟内结束，超时前 CoreMan 会改用主动推送交付结果，详见 [IM 回复生命周期](im-reply-lifecycle.md)。
- 内置命令：`reset` / `new` / `clear` / `重置` / `清空` 开始新会话，`stop` / `停止` / `暂停` / `停` 停止当前任务，`help` / `帮助` / `?` 查看帮助。
- 发言者按企业微信 userid 匹配 CoreMan 用户。群聊中企业微信可能下发加密的 `open_userid`，此时 worker 需要一个启用的企业微信平台应用（优先具备「登录」能力，其次「通知」）调用 `batch/openuserid_to_userid` 换取明文 userid，且该成员必须在应用可见范围内。换取失败时发言者身份未知：配置了白名单的 AI 员工会拒绝，未配置时身份类环境变量与业务系统授权不会下发。

### 连接企业微信（本人私聊工具）

成员绑定自己的企业微信后，在与**任意**企业微信 AI 员工的**私聊**里，可以让它以自己的身份查询和办理事情：查待办、日程、会议（含转写）、文档与表格、邮件、微盘文件和同事信息；选了相应档位后，还能建待办、日程、会议，编辑文档和表格，按明确要求发邮件、共享文档。

企业微信和飞书的授权方式不同。企业微信没有「每位用户各自授权、拿用户令牌」的开放接口，自建应用的接口也只能操作应用自己创建的日程、会议和文档。能代成员操作的只有智能机器人的「可使用权限」，而它绑在机器人上：机器人代表的是创建它的成员，调用里不带发言人（机器人编辑页「权限模式」目前只有「共享创建者的权限」，「按实际对话人授权」尚未开放）。所以 CoreMan 的做法是：

- **每位成员扫码建一个自己的「授权机器人」**，它只负责取数，不聊天、不连长连接；CoreMan 加密托管它的凭证。聊天仍由共享的 AI 员工机器人负责。
- 绑定时 CoreMan 用授权机器人的 BotID 与 Secret 换取网关令牌，查询它代表的成员（`identity/whoami`），与发起扫码的本人核对一致才托管；此后每 5 分钟复核一次。授权机器人被删除、Secret 被重置或代表的人变了，绑定立即作废，需要重新扫码。
- 本人在任何企业微信 AI 员工的私聊里，工具都用自己的这份凭证；别人私聊同一个 AI 员工，用的是他们自己的绑定，没绑定就没有这些工具。
- 协议取自企业微信官方命令行工具 wecom-cli（扫码 `work.weixin.qq.com/ai/qc/*`、令牌 `qyapi.weixin.qq.com/cgi-bin/aibot/cli/get_cli_config`、调用 `qyapi.weixin.qq.com/cli/*`），开放文档里没有。协议变更时对照官方工具更新。

#### 绑定

1. 本人的企业微信身份已同步到 CoreMan（没有同步时页面不允许扫码，因为无法核对扫码人）。企业需允许成员创建智能机器人（企业微信管理后台「管理工具 → 智能机器人 → 管理」）。
2. 最快的方式：在企业微信里私聊任意 AI 员工，发送 `连接企业微信`，点回复里的「一键授权」链接。手机企业微信里点开会自动登录 CoreMan 并直接跳到企业微信的确认页，依次点「确认创建」和「**确认授权**」，返回私聊即可看到绑定结果和档位卡片；电脑上点开会显示二维码，用手机企业微信扫码。也可以直接在网页「我的企业微信」点「扫码绑定」。链接本身不含企业微信的扫码会话码（它能换回授权机器人的 Secret），只有本人登录后页面才会拿到。确认授权会一次授予全部能力；忘了点也能绑定成功，页面会提示未授权的能力，到电脑端企业微信补授权即可。
3. 二维码等同于授权机器人的密钥，只画给本人，5 分钟内有效；页面同时提供「在企业微信中打开」的按钮，供在手机企业微信里打开 CoreMan 时使用。本人关掉页面也不影响：scheduler 每 3 秒替本人查一次；扫到凭证但暂时连不上企业微信时，同一个会话会继续重试核对。别人扫了本人的二维码，凭证代表的是扫码人，会被丢弃。
4. 绑定后在私聊里发送 `连接企业微信`（也认 `连接企微`、`绑定企业微信`）选择档位。机器人回一条说明，再推送一张选择卡片，本人勾选后点「连接」：
   - **仅读取**：只能查询。
   - **读写（不发邮件）**：另外可以创建和修改待办、日程、会议，编辑文档和表格。
   - **全部（含发邮件）**：另外可以发送、回复、转发邮件，把文档共享给同事。
   卡片 10 分钟内有效，只认发出指令的本人在同一私聊里点击。档位也可以在「我的企业微信」页面修改。没绑定时，这句话会回复绑定入口，私聊里不会出现二维码。
5. 之后直接说需要做什么，例如“看看我这周的会议”“把今天的待办列出来”。发送 `断开企业微信` 只是**暂停**，凭证保留，再发 `连接企业微信` 即可恢复；要彻底解除，在「我的企业微信」点「解除绑定」，并在企业微信里删除那个授权机器人。

Runtime 需要上报 `wecom_personal_tools_v1`（Claude 与 Codex 均支持）。

#### 授权有效期与续期

- 企业微信的能力授权**按子项各自计时约 7 天**（例如「搜索与获取邮件」和「发送邮件」分开计时），持续调用也不会顺延；到期后调用返回 850003，未授权返回 850002。企业微信没有查询到期时间的接口，也没有续期接口。
- **续期只能在电脑端企业微信**：「工作台 → 智能机器人 → 本人的授权机器人 → 可使用权限」，手机端只显示「请前往电脑端授权」。重新扫码也能恢复，但每次都会新建一个授权机器人，不推荐。
- CoreMan 按调用结果记录每项能力的状态，并按「最近一次授权时间 + 7 天」估算到期时间，在估计到期前一天通过本人最近私聊过的企业微信 AI 员工提醒一次（20 小时内不重复，过期超过 3 天不再提醒）。本人续期后在「我的企业微信」点「我已续期」，从那时重新起算。
- 企业微信在 850002 / 850003 的响应里常附带续期说明和授权页链接（`help_message`）；CoreMan 只取其中企业微信域名下的 https 链接，交给模型原样转告本人，并在页面上显示「去续期」。

#### 权限边界

- 工具**叠加**在普通助手之上：人设、技能、业务系统访问、记忆和会话都不变。只在本人与企业微信 AI 员工的私聊中挂载；群聊、机器人协作、未绑定或已暂停的用户都没有。
- 本人创建、以本人身份执行、结果只发给本人的定时任务也能使用（与飞书相同的规则）；任务配置了群、邮件、Webhook 或其他接收人，或由其他管理员“立即运行”，这一轮就不挂载。私聊里用 `coreman-cron` 技能创建和管理本人 AI 定时任务，见 [定时任务 · 成员本人任务](cron-jobs.md#成员本人任务技能)。
- 模型只看到两个工具：`wecom_method_schema`（查询某个方法的参数，取自企业微信的服务发现）和 `wecom_call`（调用）。能调用的方法是 CoreMan 固定的白名单，再按档位收窄；企业微信那边是否授权了对应能力，以调用结果为准。
- 不提供的能力：读取会话消息（企业微信只对群聊开放，10 人以上企业也不可用，且涉及他人隐私）、以机器人身份发消息（CoreMan 本来就会回复）、本地文件的上传下载与导入（参数是运行时机器上的路径，服务端读不到）、删除工作表、修改文档加入规则、智能表格写入（10 人以上企业不可用）。
- 企业微信自己的规则：本人的数据可以读取；待办、日程、会议只能修改授权机器人创建的；文档与表格可以编辑本人有权限的；以本人授权发出的邮件，发件人显示为授权机器人。
- 写入与外发只在用户本次明确要求时执行，工具返回的内容作为不可信的外部资料交给模型；这是提示词约束，不是隔离。本人资料写进共享记忆或工作目录后，同一 AI 员工的其他会话可能看到，同样只靠提示词约束。
- 挂了企业微信工具的私聊轮次在对话记录（`chat_logs.private`）和会话页里只有本人能查看，机器人管理员与平台管理员都看不到；未挂载时的企微私聊仍按原规则对管理员可见。
- 授权机器人的凭证与网关令牌加密保存在数据库，只在服务端使用，不传给模型或 Runtime。能读数据库并持有主密钥的人，技术上可以用这份凭证以本人身份操作企业微信，这与其他托管凭证的风险相同。

需要数据库迁移 `0041`、`0042`。上一版本按 AI 员工记录的连接（`wecom_personal_grants`）不再使用，已连接的成员需要重新扫码绑定一次；该表留给滚动升级期间的旧版本，后续迁移删除。

## 二、平台应用（企业自建应用）

平台应用是企业微信自建应用在 CoreMan 中的登记，按勾选的能力启用对应功能。不使用这些功能时可以不配置；但群聊身份识别（见上文）依赖一个具备「登录」或「通知」能力的应用。

### 能力与所需字段

| 能力 | 用途 | 企业 ID | 应用 ID | 密钥 | 回调 Token / 回调 AES Key |
|---|---|---|---|---|---|
| 通讯录同步 | 拉取部门与成员，建立 CoreMan 用户与企业微信身份的绑定 | 必填 | — | 必填 | — |
| 登录 | 管理台企业微信扫码登录、企业微信内网页登录 | 必填 | 必填 | 必填 | — |
| 通知 | 以应用消息通知员工（定时任务结果、求助、运行告警等） | 必填 | 必填，须为纯数字 | 必填 | — |
| 回调 | 接收员工对求助通知的回复（文字与媒体） | 必填 | 必填 | 必填 | 必填 |

字段来源：

- **企业 ID**：企业微信管理后台企业信息中的企业 ID（CorpID）。
- **应用 ID**：在管理后台应用管理中创建自建应用后，应用详情里的 AgentId。
- **密钥**：同一应用的 Secret。
- **回调 Token / 回调 AES Key**：在该应用的接收消息（API 接收）设置中生成的 Token 与 EncodingAESKey。
- **扩展参数**：企业微信应用当前不读取该字段，保持 `{}`。

一个平台应用可以同时勾选多个能力。保存后密钥类字段只显示脱敏值；编辑时保留脱敏值表示不修改。

### 企业微信侧配置

- **企业可信 IP**：按企业微信官方开发指南，新创建的自建应用必须在管理端配置可信 IP，只有可信 IP 能调用服务端接口。把运行 CoreMan api、worker、scheduler 与网关的主机出口 IP 加入该应用的可信 IP。
- **可见范围**：成员必须在应用可见范围内，才能被通讯录同步读到、通过企业微信登录、收到应用通知、被换取 `open_userid`。通讯录同步从根部门（ID 1）递归拉取成员，建议可见范围覆盖需要使用 CoreMan 的全部部门。
- **可信域名**（登录）：登录跳转地址为 `{PUBLIC_BASE_URL}/api/auth/wecom/callback`。企业微信要求 `redirect_uri` 的域名已配置为应用的可信域名（网页授权）或 Web 网页授权回调域名，且必须与 `PUBLIC_BASE_URL` 的域名完全一致，带端口时端口也要一致，否则跳转时提示 `redirect_uri参数错误`。
- **接收消息**（回调）：保存带「回调」能力的平台应用后，列表会显示「求助回复回调地址」`{PUBLIC_BASE_URL}/api/callbacks/wecom/{平台应用 ID}`。把该地址与上面的 Token、EncodingAESKey 填入应用的接收消息设置。企业微信须能通过公网 HTTPS 访问该地址；URL 验证使用 GET，消息使用 POST。完整说明见 [人工求助](escalations.md)。

### 在 CoreMan 中配置与验证

1. 以平台管理员身份打开「平台应用」，新建平台为「企业微信」的应用，勾选能力并填写字段。
2. 点击「测试」：CoreMan 使用企业 ID 与密钥获取 access_token，成功时提示连接测试成功；失败时显示企业微信返回的错误码。
3. 具备「通讯录同步」能力时点击「同步」，在「同步记录」查看结果。员工必须先通过同步建立企业微信身份，才能登录或被识别为发言者。
4. 具备「登录」能力时，退出后在登录页使用企业微信登录验证。存在多个启用的登录应用时使用最早创建的那个。平台登录验证成功后，可在设置中关闭引导管理员登录。
5. 具备「通知」或「回调」能力时，按 [定时任务](cron-jobs.md) 或 [人工求助](escalations.md) 的说明发送一次测试。

## 常见故障排查

网关与 worker 输出 JSON 日志，下表中的事件名即日志里的 `event` 字段，可用 `./deploy/coreman logs <服务>` 查看。

### 智能机器人连接

| 现象 | 日志事件 / 提示 | 原因与处理 |
|---|---|---|
| 运行状态显示「认证失败」 | `wecom_subscribe_rejected`（带 `errcode`） | 企业微信拒绝订阅，常见为 BotID 或 Secret 错误，或机器人未切换到 API 模式长连接。核对凭证后保存，网关会用新凭证重连 |
| 运行状态显示「已被顶替」 | `wecom_ws_kicked`、`wecom_ws_kick_fused`、`lease_released_after_kick_fuse` | 同一机器人有另一个连接。300 秒内被顶替 10 次后网关停止重连并释放该机器人，30 秒后才会重新认领。停掉使用同一凭证的其他程序或部署 |
| 反复「未连接」「连接中」 | `wecom_ws_disconnected`、`wecom_ws_idle_timeout` | 网络中断或 90 秒内未收到任何帧。检查到 `openws.work.weixin.qq.com` 的出站网络；重连间隔从 2 秒指数退避到 60 秒 |
| 机器人已启用但网关不连接 | `bot_credentials_incomplete`、`bot_credentials_unreadable` | 凭证缺少 BotID / Secret，或 `MASTER_KEY` 变更导致无法解密。重新填写凭证；丢失原 `MASTER_KEY` 时已加密的凭证无法恢复 |
| 群里发消息没有回应 | — | 群聊必须 @ 机器人；确认该机器人已被加入群聊 |
| 某类消息没有回应 | `wecom_msgtype_unsupported` | 消息类型不在支持列表中 |
| 新建员工时提示「企业微信拒绝了这组 Bot ID 与 Secret」 | HTTP 422，`wecom_manual_credentials_rejected`、`wecom_provision_verify_failed`（带 `errcode`） | 凭证错误，或机器人未切换到 API 模式长连接。核对后重试；扫码创建的机器人在弹窗中点「重新校验并创建员工」 |
| 新建员工时提示「暂时无法连接企业微信校验凭证」 | HTTP 502 | API 服务无法出站访问 `openws.work.weixin.qq.com`，或企业微信没有按时应答 |
| 提示「企业微信暂时无法生成二维码」或二维码一直停在等待 | HTTP 502，`wecom_provision_unexpected_response` | API 服务无法访问 `work.weixin.qq.com`，或扫码接口已改版。暂时在「平台设置」关闭扫码创建，改为手动填写凭证 |
| 提示「扫码创建企业微信机器人已关闭」 | HTTP 409 | 平台管理员关闭了扫码创建，改为手动填写凭证 |

### 对话处理

| 现象 | 日志事件 / 提示 | 原因与处理 |
|---|---|---|
| 回复「抱歉，您没有使用此机器人的权限」 | `denied_not_allowed` | 使用白名单非空，而发言者不在名单内或身份无法识别。确认该员工已通过通讯录同步绑定企业微信身份；群聊中另见下一行 |
| 群聊中身份识别失败 | `openuserid_app_unavailable`、`openuserid_resolve_failed` | 没有启用的、具备「登录」或「通知」能力的企业微信平台应用，或成员不在该应用可见范围，或主机不在可信 IP 中。失败结果会缓存 5 分钟 |
| 回复「AI 连接出现错误（运行时 未配置）」 | `relay_unavailable` | AI 员工没有绑定运行时，或绑定的运行时实例已停用。在 AI 员工详情中「切换运行时」 |
| 保存 AI 员工时提示「工作目录必须位于所选运行时的项目主目录之下」 | HTTP 422 | 工作目录不在节点安装时填写的项目主目录下，或与项目主目录相同 |
| 对话失败，驱动日志出现 `fork/exec .../claude: no such file or directory` | 节点 `claude.log` / `codex.log` | 常见原因是工作目录在节点上不存在，子进程无法以它为工作目录启动。先创建目录并确认运行用户可读写，再核对 CLI 路径，不要只根据报错认定 CLI 缺失 |

### 连接企业微信

| 现象 | 提示 | 原因与处理 |
|---|---|---|
| 「扫码绑定」按钮不可用，提示账号未同步 | HTTP 422 | 本人的企业微信身份还没有同步到 CoreMan，请管理员同步通讯录 |
| 扫码后页面提示「扫码的不是你本人」 | `not_self` | 二维码被别人扫了，凭证代表的是扫码人，已丢弃。本人重新扫码 |
| 扫码后页面提示账号对不上 | `identity_unlinked` | 企业微信返回的授权人在 CoreMan 里找不到对应用户：本人身份未同步，或没有可用的企业微信平台应用来换算密文 userid |
| 绑定成功但各项能力都是「未授权」 | 850002 | 扫码时没有点「确认授权」。到电脑端企业微信「工作台 → 智能机器人 → 授权机器人 → 可使用权限」授权后，在页面点「重新检查」 |
| 发送“连接企业微信”提示当前运行时不支持 | — | Runtime 还没有上报 `wecom_personal_tools_v1`，升级运行时节点 |
| 调用返回 `capability_state: expired` / `unauthorized` | 850003 / 850002 | 对应能力过期或未授权。到电脑端企业微信的「可使用权限」续期，再在页面点「我已续期」 |
| 调用返回 `credentials_rejected`，页面显示需要重新绑定 | — | 授权机器人被删除或重置了 Secret。重新扫码绑定 |
| 调用返回 `authorization_changed` | — | 本人暂停、解除、重新绑定或修改过档位，下一轮对话自动生效 |
| 同事发不进消息给 AI 员工 | — | 扫码建的 AI 员工机器人默认「仅个人使用」，在企业微信「使用模式」改为「多人使用」 |

### 平台应用

| 现象 | 提示 | 原因与处理 |
|---|---|---|
| 「测试」失败 | `企微接口错误 <errcode>: <errmsg>` | 按错误码核对企业 ID、密钥与可信 IP；显示「连接失败」时检查到 `qyapi.weixin.qq.com` 的网络 |
| 同步失败，提示 48009 | 「新增 IP 不能读取通讯录详情(48009)…」 | 当前主机 IP 不在可信 IP 中，加入后重试 |
| 同步中止 | 「目录为空，疑似抓取异常，已中止」「一次同步停用 N 人，超过上限 100，已中止」「邮箱与手机号指向不同账号，已中止归并」 | 为避免误停用成员，同步整体回滚、不做任何修改。检查可见范围与应用权限，或先处理通讯录中的邮箱/手机号冲突 |
| 登录跳转提示 `redirect_uri参数错误` | 企业微信页面 | 可信域名与 `PUBLIC_BASE_URL` 不一致 |
| 登录后回到登录页并带 `error` 参数 | `wecom_not_configured`、`not_member`、`user_not_found`、`user_disabled`、`invalid_state`、`code_replayed`、`wecom_error` | 依次为：没有启用的登录应用；不在应用可见范围的非企业成员；尚未同步到 CoreMan 的员工；员工已停用；登录状态超过 10 分钟或不是在同一浏览器发起；授权码重复使用；企业微信接口报错（日志 `wecom_login_failed` 带 `errcode`） |
| 求助回复收不到 | HTTP 403「回调应用不可用或不唯一」「回调配置不完整」「回调验证失败」「回调所属企业或应用不匹配」「回调消息已过期」 | 核对回调地址中的平台应用 ID、Token、EncodingAESKey、企业 ID 与 AgentId；服务器时间偏差超过 600 秒时签名校验会失败 |
| 应用通知发送失败 | 「通知应用配置不完整或平台未支持」「接收人不在可用范围或没有许可」 | 应用 ID 须为数字 AgentId；接收人须在应用可见范围内 |
