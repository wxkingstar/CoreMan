# 个人凭证

AI 员工执行任务时需要某个系统的账号、密码或 API Key，可以向**当前用户本人**索取。用户通过飞书卡片表单或企业微信网页提交，内容不经过聊天，由 CoreMan 直接加密保存。之后只有这个用户本人触发的轮次，才会把这份凭证作为环境变量注入 AI CLI。

## 是什么

- **按（AI 员工, 用户）隔离**：在 A 里提交的凭证只给 A 用，换到 B 要重新提交；同一个人的凭证不会出现在别人触发的轮次里。
- **索取什么由 agent 判断**，不需要管理员预先声明。平台只做技术上必须的校验（见「agent 怎么索取」）。
- **加密保存**：每条凭证单独用主密钥加密，密文绑定（AI 员工, 用户, 变量名）这一行的身份；数据库里只有密文，任何接口都不返回密文字段的值。
- **只在本人触发的轮次注入**：本人私聊、群聊中本人 @ 机器人、本人创建的定时任务、提交之后的续接轮。同事求助后的续接轮、AI 员工之间的协作轮不注入。
- **不限数量与频率**：不限制每人凭证总数，也不限制索取次数。

## 用户怎么用

### 飞书

1. agent 判断缺少凭证，在你与 AI 员工的**私聊**里发来一张「🔒 需要你的个人凭证」表单卡片，列出用途和要填的字段（密码类字段显示为「•」）。你在群里 @ 机器人触发时，表单同样发到私聊，群里只留一句「已私信你一张安全表单」。
2. 填写后点「加密提交」，卡片变成「✅ 已保存 …（内容不显示）」。
3. AI 员工在原来的会话里继续刚才的任务。
4. 表单 1 小时内有效，过期后卡片变成「表单已过期」，需要让 AI 员工重新发起。卡片里的值最长 1000 个字符；配置了飞书登录应用时，卡片多一个「内容较长？用网页填写」的入口，网页上限 4096。
5. 只有发起人本人点提交有效。别人点同一张卡片（例如表单发回了原群）会被忽略：不提交、不改卡片，飞书只返回统一的受理提示，发起人的表单保持打开。卡片上提交的值不合规（例如为空或含换行）时，这次请求会被取消并提示，让 AI 员工重新发起即可。

没有私聊记录或平台身份时，群聊里发起的请求会把表单直接发到原群并 @ 发起人（`password` 输入框的内容只在填写人本地可见，别人点提交也会被拒）。定时任务没有私聊记录时无法送达，见下文的 409。

### 企业微信

企业微信的模板卡片没有文本输入，所以用网页：

1. agent 发来一条链接「点这里安全填写」（1 小时内有效，只有你本人能打开）。
2. 点开后用企业微信登录，在网页里填写并提交。别人打开同一个链接只会看到 403。
3. 提交后 AI 员工以主动消息的方式在原会话里继续。

手机必须能访问 `PUBLIC_BASE_URL`，见「部署前提」。

### 我的凭证

两个平台都可以在控制台的「我的凭证」页（`/my-credentials`）查看、更新、删除自己的凭证：

- 按 AI 员工分组，显示标签、变量名、更新时间、最近使用时间。
- 密文字段只显示「已设置（不显示）」；账号这类非密文字段显示原值。
- 更新就是重新填写一遍，删除后下一轮不再注入。
- 只能操作本人的数据；平台管理员和 AI 委员会也无法查看或代管别人的凭证。

没有配置飞书登录应用时，飞书用户打不开网页，需要覆盖旧值就让 AI 员工用同一个变量名重新索取。

## 注入范围

| 轮次 | 注入谁的 | 下发索取令牌 |
|---|---|---|
| 私聊，已验证的本人发言 | 发言者 | 是 |
| 群聊，已验证的本人 @ 机器人 | 发言者（只有当前发言者的，群里换人发言就换人） | 是 |
| 定时任务执行 | 任务创建人（执行人） | 是 |
| 提交凭证后的续接轮 | 发起人 | 是 |
| 同事求助后的续接轮 | 不注入 | 否 |
| AI 员工之间协作的轮次 | 不注入 | 否 |
| 发言者未知、已停用、引导管理员 | 不注入 | 否 |

注入时的规则：

- 优先级：个人凭证 > AI 员工 env > 技能 env。
- 注入前再按「禁用键」「平台保留键」过滤一遍，策略收紧后存量数据也不会越界；`COREMAN_CREDENTIAL_` 前缀是保留前缀，AI 员工 env 和技能预设里的同名变量一律丢弃。
- 某条解密失败时跳过这一条，日志只记变量名，不影响本轮。
- 系统提示词只列出发言者已保存的变量**名字**，不含值；并告诉 agent 缺凭证时如何索取，以及不得让用户在聊天里发密码、不得打印或写入文件。
- 「最近使用时间」距上次超过 1 小时才更新，避免每轮都写库。

## agent 怎么索取

在会注入个人凭证的轮次里，平台下发两个环境变量：

- `COREMAN_CREDENTIAL_URL`：`{PUBLIC_BASE_URL}/api/runtime/credentials/requests`
- `COREMAN_CREDENTIAL_TOKEN`：本轮能力令牌，加密的声明（任务、AI 员工、用户、来源会话与过期时间）。有效期为本轮超时时间加 300 秒，并且**只在签发它的那一轮仍在运行时有效**，轮次结束后即失效。

请求：

```bash
curl -sS -X POST "$COREMAN_CREDENTIAL_URL" \
  -H "Authorization: Bearer $COREMAN_CREDENTIAL_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "fields": [
      {"key": "DEMO_USERNAME", "label": "Demo 系统账号", "secret": false},
      {"key": "DEMO_PASSWORD", "label": "Demo 系统密码", "secret": true, "placeholder": "登录 Demo 系统用的密码"}
    ],
    "purpose": "查询你本月的订单需要登录 Demo 系统"
  }'
```

字段说明与校验：

- `fields`：1–20 个，同一请求内变量名不能重复。`secret` 默认为 `true`（密码输入框、强制出站脱敏）；账号这类非机密字段设为 `false`。
- `key`：符合 `^[A-Z][A-Z0-9_]{0,63}$`；不以 `COREMAN_` 开头；不能是平台保留变量或会改变运行时行为的变量。
- `label` 不超过 50 字，`placeholder` 不超过 100 字，`purpose` 不超过 300 字，用途按纯文本渲染。
- 用户提交的值：每个字段必填，去首尾空白，长度 1–4096（飞书卡片 1000），不能包含换行和控制字符。

响应：

| 状态码 | 含义 |
|---|---|
| `202` | `{"status":"form_sent","request_id":"…"}`，表单已发出 |
| `200` | `{"status":"already_pending","request_id":"…"}`，同一用户在本 AI 员工下已有变量名集合完全相同、来源也相同（同一个对话会话，或同一个定时任务）、未过期的请求，不重复发；来源不同则另发一张表单 |
| `401` | 令牌无效或已过期 |
| `403` | 请求带了浏览器 `Origin` 头；或来源那一轮已结束、用户或 AI 员工已停用 |
| `409` | 无法送达，不创建请求：没有可发送的会话（例如定时任务来源且没有私聊记录），或企业微信未配置启用了登录能力的应用 |
| `413` | 请求体超过 64 KiB，不创建请求 |
| `422` | 请求体不是 JSON，或字段不合法，逐个说明原因 |

两种成功响应都带一句给 agent 的话：已向用户发送安全表单，请简短告诉用户去填写，然后结束本轮，提交后会自动续接。定时任务来源的令牌拿到的是另一句：定时任务不会续接，请在输出里说明本次缺少凭证并结束本轮，提交的值从下一次定时运行起生效；同一段话也写在这类轮次的系统提示词里。

表单发到哪里由平台决定，而不是 agent：只有同时存在用户与该 AI 员工的私聊记录和用户的平台身份时才发私聊；否则对话来源的请求发回来源会话（飞书群里带 @ 提及），定时任务来源的请求被拒绝（409）。

用户提交后的网页接口（飞书网页入口与企业微信共用，需要浏览器登录会话，写操作要求 CSRF）：

| 接口 | 说明 |
|---|---|
| `GET /api/me/credential-requests/{id}` | 只有发起人能读：字段、用途、AI 员工名、状态、过期时间 |
| `POST /api/me/credential-requests/{id}/submit` | 请求体 `{"values": {KEY: value}}`。`403` 非发起人，或 AI 员工已停用、账号不可用，`409` 已提交过，`410` 已过期或已取消，`422` 值不合规 |

### 提交之后

- **来源是对话**：平台排一个 `credential_resume` 任务，在原会话里续接。续接消息是系统写好的固定文本，只含变量名；这一轮照常按发起人注入凭证。
- **只续接提问的那个对话**：表单记着发起索取那一轮用的 relay 会话，续接前核对它仍是该会话键当前的会话。表单发出后如果用户重置、清除或切换了会话，提交时值照常保存，但不再续接：用户收到「凭证已保存。对话已重置，请重新发起刚才的请求。」，再让 AI 员工做一遍即可。重置之前发出的表单也不会被重置后的新对话复用，新对话需要时会另发一张。
- **来源是定时任务**：不续接，只私信「已保存，下次执行时生效」。
- **一次填写结算所有在等的表单**：同一用户、同一 AI 员工下，变量名全部被刚保存的值覆盖的其他未过期请求（例如另一个会话、或定时任务发出的同名表单）一并标记为已提交，各自续接各自的来源；不写第二次值，也不多记审计。
- **AI 员工已停用时提交被拒绝**。提交之后 AI 员工被停用、或运行节点不可用，续接轮不会运行，用户收到「凭证已保存，下次对话时生效。」（停用的 AI 员工网关没在跑，通知会等重新启用后发出）。
- 凭证失效（例如外部系统返回 401）时，agent 用同一个变量名重新索取，提交后覆盖旧值。

## 部署前提

- **企业微信**：需要一个启用了「登录」能力的自建应用（登录页走 OAuth）。没有时索取接口返回 409，agent 会告诉用户联系管理员。
- **手机要能访问 `PUBLIC_BASE_URL`**：企业微信用户点链接就是打开这个地址。
- **飞书**：配置了飞书登录应用时，卡片多一个网页入口，用户也能打开「我的凭证」页；没有时只有卡片表单。
- **飞书应用要有 user_id 权限**（`contact:user.employee_id:readonly`，通过 CoreMan 创建的应用默认已申请）：和所有卡片交互一样，表单提交靠回调里的 `operator.user_id` 核对点击人；没有这项权限时回调里没有它，点击会被当作非本人而忽略。
- **数据库迁移 `0054`**：只新增 `personal_credentials`、`credential_requests` 两张表，不改旧表。运行节点不用升级：节点只拦截几个固定的 `COREMAN_*` 令牌名，新的 `COREMAN_CREDENTIAL_` 前缀原样到达 CLI。
- **滚动升级顺序**：先跑迁移 0054，再升级 worker，最后升级网关和 API。表先建好，能处理新任务类型的 worker 先就位，最后才让网关和 API 开始产生这些任务。
- 升级窗口内，旧 worker 不认识 `credential_resume` 任务，认领到就会直接失败（而不是把来源消息当新消息重跑一遍）；旧 worker 认领到 `credential@` 的飞书点击，会按未知卡片结束，这次点击就丢了，用户重新提交即可，网关已封存的那份副本在保留期内仍是密文。升级完成后新提交的续接不受影响。

## 安全边界

### 能保证

- **提交不经过聊天**：值走飞书卡片回调或网页接口，不进入模型上下文、不进入对话记录。表单卡片由系统构建，模型写的卡片会被剥掉 `form` 和 `input`，无法伪造这种表单。
- **飞书回调先封存再落库**：网关在写库之前就把表单值加密（密文绑定这次请求），入站事件和任务载荷里只有密文，原始回调里的 `form_value` 被清空；网关拿不到加密器时直接丢弃这次回调，宁可让用户重填，也不落明文。
- **处理后擦除副本**：worker 处理这次点击时核对点击人、解密、保存，并把封存副本从任务和入站事件里删掉；处理器的每个退出路径都会擦除，包括崩溃（在全新的事务里再擦一遍）。没有走到处理器的点击任务（例如 worker 一直没认领），在 90 天的常规保留期内只留有这份加密副本。
- **存储**：逐行加密，数据库里只有密文；把一个人的密文挪到别人或别的变量名上，解密会失败。任何接口都不返回密文字段的值，包括 AI 委员会和平台管理员；与机器人 env 的完整查看不同。
- **使用**：提示词约束，加上强制出站脱敏：密文字段的值（长度不少于 6）一律加入本轮的脱敏集合，不论变量叫什么名字，覆盖 IM 投递、对话记录、结果分类和定时任务结果。
- **审计**：保存、更新、删除都有审计记录，只记 AI 员工、用户和变量名。

面向用户的文案只承诺「提交内容不经过聊天、不发送给 AI 模型」，不承诺「AI 永远看不到」。

### 不能保证

- **agent 能通过 shell 读到自己的环境变量。** CLI 以免审批模式运行，`env`、`printenv` 都读得到注入的凭证。如果 agent 把值打印出来，值就进入了模型上下文；如果它被网页或文件里的提示注入诱导，还可能把值发往外部。这一层只靠提示词约束和出站脱敏兜底。
- **运行节点上 CLI 自己的会话记录和会话查看器不做脱敏**，值一旦被打印出来就会留在那里。
- **用户仍可能无视提示，直接把密码发在聊天里**；那样的内容走普通对话通道，不受本功能保护。
- **企业微信里 agent 仍可以自己发一条样式与系统消息相仿的 markdown 链接**，把用户引到别处。受保护的只有系统构建的那条链接消息，用户应当使用带固定安全说明的那一条里的链接。
- **脱敏只做原值精确匹配**：值在打印前被编码、拆开或做过其他变换（例如 base64、按字符拆行），就不会被替换。
- **短值不会被脱敏**：不到 6 个字符的密文字段照常注入，但不会从输出里替换；非密文字段（`secret` 为 `false`）也不强制脱敏。
- 请勿在表单里填写飞书、企业微信或邮箱的登录密码；表单上的安全说明也这样提示。

要彻底不让 agent 接触明文，需要「凭证代理」（env 里只放占位符，由 CoreMan 侧在请求发出时替换成真值），一期不做。

## 数据保留

- 凭证（`personal_credentials`）保留到本人删除，或 AI 员工、用户被删除（级联删除）。
- 索取请求（`credential_requests`）：未提交且超时的请求由清理任务置为已过期，有飞书卡片时同时把卡片改成「表单已过期」；已提交、已过期、已取消的请求保留 90 天后删除，与任务的保留期一致。请求里本来就没有任何值，只有字段名、标签和用途。
- 请求有效期 1 小时；令牌随来源那一轮结束而失效。

排查顺序：`credential_requests` 的状态 → `request_outbox_id` 对应出站项的状态和 `last_error`（表单是否发出）→ 飞书点击对应的 `card_action` 任务（`task_id` 形如 `credential@<请求 ID>`）→ `resume_task_id` 的任务与会话记录。
