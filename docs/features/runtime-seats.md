# 运行时席位

一台运行时上的 Claude Code 或 Codex 可以登录多个账号（席位），同一时间只用其中一个。某个账号的额度用完时，平台管理员在管理台把这台机器切到另一个席位，机器上的 AI 员工不用换运行时，接着工作。整个过程不需要登录到运行时机器上。

## 管理入口

「运行时管理」节点列表的操作列里点「席位」（只有平台管理员能看到）。弹框按 AI 类型分别列出席位：名称、账号、登录状态、额度，以及「登录」「设为当前」「移除」。

- **默认席位**：CLI 原来的位置（`~/.claude` / `~/.codex`，或服务环境给定的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME`）。不能移除。
- **添加席位**：填一个名称（最多 60 字）。节点在 `<数据目录>/seats/<AI 类型>/<席位 id>/` 建配置目录，然后点「登录」。
- **登录**：节点上的 CLI 发起登录，管理台给出授权链接。
  - Claude：在浏览器里用这个席位的账号授权，把页面上显示的认证码贴回管理台，点「完成登录」。
  - Codex：设备码登录。在浏览器里用这个席位的账号登录并输入管理台显示的一次性代码，再点「我已完成」。
  - 令牌由 CLI 自己保存在该席位目录里，平台不保存。登录会话 15 分钟有效。
- **设为当前**：只能选已登录的席位。新对话用新席位；切换时正在进行的对话在原席位上跑完。
- **移除**：不能移除当前席位。节点会在该席位上退出登录并删除它的配置目录。

## 共用与不共用的内容

每个席位的凭据与账号状态分开保存。下面这些在席位目录里是指向默认席位的软链，各席位共用，所以换席位后员工的会话还能续上：

| AI | 共用 |
|---|---|
| Claude | `projects/`（会话与记忆）、`plugins/`、`skills/`、`agents/`、`commands/`、`hooks/`、`settings.json`、`CLAUDE.md` |
| Codex | `sessions/`、`archived_sessions/`、`prompts/`、`skills/`、`config.toml`、`AGENTS.md` |

不共用的有：CLI 自己的全局状态文件（Claude 的 `.claude.json`，其中包括用户级 MCP 配置），以及 MCP 技能的 OAuth 令牌。已授权的 MCP 技能切到新席位后需要重新授权。

## 额度

当前席位的额度显示在实例上，和原来一样。切换时，旧席位当时的额度存进 `relay_servers.seat_quotas`，再换上新席位上一次切走时存下的额度；从没用过的席位额度为空，等下一次对话或每小时的采集刷新。额度提醒和额度表照常按当前席位计算。

## 实现

- 当前席位写进守护进程的环境变量，之后启动的驱动、健康检查、技能安装和 MCP 授权都继承它。
- 切换时守护进程在新 socket 上起一个继承新席位环境的驱动，接后续请求；旧驱动等它手上的请求结束再停。
- 节点在心跳的 `capabilities.<AI>.seats` 上报各席位的账号与登录状态，并声明 `seat_switch_v1`。
- 接口：`POST /api/admin/runtime-nodes/{节点}/{AI}/seats`，以及 `…/seats/{席位}/login`、`…/login/complete`、`…/activate`、`DELETE …/seats/{席位}`，都只给平台管理员，并记审计（`runtime.seat_create`、`runtime.seat_login`、`runtime.seat_activate`、`runtime.seat_remove`）。

需要数据库迁移 `0069`，运行时节点也要升级；未升级的节点在弹框里提示先升级。
