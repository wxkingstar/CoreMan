# 调度员知识库

群聊调度员要判断一件事归谁、怎么拆、找谁定，需要了解业务、系统、谁负责什么，以及过去的决定。CoreMan 每天把平台里对成员公开的内容抽成事实，增量编译成一套 Wiki，放在调度员工作目录的 `docs/` 下；`AGENTS.md` 里有一段自动维护的路由摘要指向它。

设计与取舍见 [设计稿](../superpowers/specs/2026-11-28-dispatcher-knowledge-base.md)。目前实现的是第一期：不读群对话，没有管理台页面，用命令行管理。

## 读什么，不读什么

读四类来源：

| 来源 | 内容 |
|---|---|
| 各 AI 员工的规则文档 | 工作目录里的 `AGENTS.md` 与 `docs/`（自带代码仓库的员工也读） |
| 业务系统目录 | 系统说明、使用指引、模块与操作的一句话说明、哪些 AI 员工可用；不含地址 |
| 名录 | 团队、成员的姓名与职位、AI 员工的说明、职责、提示词、创建人与管理成员 |
| 任务平台 | 已完成的任务：网页上建的、多人群里调度出来的，以及它们的子任务 |

不读，由代码排除：

- 个人助理的任何内容，以及牵涉个人助理的任务。
- 私聊、单人群里发起的任务；认不出是不是多人群的也不读。
- 镜像进任务平台的业务系统任务和求助记录。
- 成员的邮箱、手机号；服务账号；停用的员工。

对话原文不进调度员的工作目录。平台从库里读材料，交给一轮抽取，只留下抽出的事实条目。

## 一次运行做什么

1. **收集**：按上面的范围取上次之后新增的材料。文档按标题切段，只取新出现的段；任务按完成时间往后走。
2. **抽取**：每批材料跑一轮，输出事实条目。条目用自己的话写，不带原话；人只写职责，数据只写口径。只抽调度员判断「归谁、怎么拆、找谁定、有什么边界」用得上的内容：执行的人自己手册里的操作细节（命令、路径、逐步步骤）和每个 AI 员工都一样的通用约定不抽，一批通常 3 到 8 条。
3. **规则过滤**：条目里有手机号、邮箱、证件号、密钥、带参数的链接、网络地址、金额、长数字串的，整条丢弃，只记下命中的规则名。
4. **编译**：在调度员的工作目录里跑一轮，把新条目并进 `docs/` 下的页面。每句知识末尾带来源和条目编号，例如 `（T-128，K-345）`、`（规则文档 订单助手，K-346）`。新旧说法冲突时保留新的，旧的移到「已变更」小节。
5. **检查**：改过的文件再过一遍规则过滤。命中的让模型删掉，最多两轮；仍有命中时这次运行记为「需要人看」。几次编译都没落到任何一页的条目不再重试。

抽取和编译都在调度员所在的运行时节点上跑：先用 Claude，额度超过阈值或不可用时用 Codex，模型用该后端的默认模型。两个都不可用时这次不跑，进度不动，之后几小时里每小时再试。额度阈值是为了把余量留给调度回合，它们共用同一个运行时的额度。

## 开启

命令在平台容器里执行（`./deploy/coreman knowledge …`）：

```bash
./deploy/coreman knowledge set --bot <调度员的标识> --enable
```

承接知识库的 AI 员工必须是调度员角色，全平台只有一个。开启后 scheduler 每天在约定时间之后跑一次（默认 2 点，时区默认 `Asia/Shanghai`）。

第一次对已有数据跑一轮（冷启动）：

```bash
./deploy/coreman knowledge run --cold-start
```

不加 `--apply` 只列出会读多少材料，不调用模型、不写任何东西。确认后加 `--apply`。冷启动每次最多 500 批、4 小时，没跑完的之后每晚接着跑，跑完自动回到日常上限（200 批）。

其他设置：

```bash
./deploy/coreman knowledge set --hour 3 --timezone Asia/Tokyo   # 每天几点开始
./deploy/coreman knowledge set --quota-7d 60 --quota-5h 70      # 额度用到百分之几就不再用
./deploy/coreman knowledge set --disable                        # 关闭每天自动运行
./deploy/coreman knowledge status                               # 设置、条目计数、最近几次运行
```

## Wiki 的结构

```
AGENTS.md                调度员的定位由人写；起止标记之间的「路由摘要」由编译维护
docs/
  index.md               全部页面的目录
  log.md                 编译日志
  company/               业务一页纸、业务线、术语与口径
  systems/<系统>.md       每个系统一页
  roles.md               职责名录
  bots/<员工>.md          每个 AI 员工一页
  decisions/<年月>.md     决策记录
  playbooks/<场景>.md     常见场景怎么派
```

`AGENTS.md` 里 `<!-- knowledge:routes:start -->` 与 `<!-- knowledge:routes:end -->` 之间的内容由编译维护，其余部分编译不改。调度员的定位、原则和授权边界请写在标记之外。

配置了[规则备份](rules-backup.md)时，Wiki 随 `AGENTS.md` 和 `docs/` 每天提交到备份仓库，可以在那里看每天的改动。

## 已知限制

- 抽取回合会在节点上留下这一轮的 CLI 会话记录。第一期的来源都是平台里对成员公开的内容；群对话接入前会补上清理。
- 外部群里调度出来的任务没有单独排除。调度员进不进外部群请自行控制。
- 规则过滤是兜底，会误伤（例如带金额的规则说明会被丢弃），也可能漏。首版 Wiki 建议全量看一遍。
- 没有管理台页面，没有编译后的通知；运行结果用 `knowledge status` 看，或看 scheduler 日志里的 `knowledge_run_done`。
