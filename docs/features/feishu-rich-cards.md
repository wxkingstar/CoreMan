# 飞书富卡片回复

飞书 AI 员工的回复用飞书卡片 JSON 2.0 呈现：除了 Markdown 正文，还能显示图表、表格、指标块、图文、时间线、提示条和彩色标题栏，浅色和深色主题下都清楚。卡片不支持的内容才退回 Markdown。

## 开关

AI 员工编辑页 →「更多设置」→ 体验 →「富卡片回复」，只对飞书 AI 员工显示，默认开启。

- 开启：system prompt 的「本轮附加能力」段落里多一段块语法说明（约 800 token），回复结束时编译成富卡片。
- 关闭：不挂说明段，回复仍是一张卡片，但块全部显示成普通 Markdown。

需要数据库迁移 `0049`（`bots.rich_cards`，默认 `true`）和 `0050`（`feishu_deliveries.layout`，流式布局）。

## 写法

模型照常写 GFM Markdown。需要富内容时，写一个 info string 为 `card:<类型>` 的围栏代码块，内容是一个 JSON 对象：

````markdown
订单比上周多 12%，退款率略升。

```card:kpi
{"items": [{"label": "订单", "value": 97, "delta": "+12.6%", "good": true},
           {"label": "退款率", "value": "2.1%", "delta": "+0.4pt", "good": false}]}
```
````

块里只写数据和语义；颜色、尺寸、字号、深浅主题适配都由平台决定。JSON 解析是宽松的（尾逗号、中文引号能纠正）；格式不对的块按原文显示成代码块，不会让整条回复失败。字段以 `coreman/core/richtext/schema.py` 为准。

| 类型 | 用途 | 主要字段 |
|---|---|---|
| `header` | 卡片标题栏（放在最前面，只取第一个） | `title`、`subtitle`、`tags[{text,color}]`、`color`（green 完成、orange 警告、red 异常） |
| `kpi` | 指标块，一行 2–4 个，手机上自动 2×2 | `items[{label,value,delta,good,note}]`、`columns`、`size` |
| `chart` | 图表 | 见下文 |
| `table` | 需要列类型时的表格（普通 GFM 表格会自动转换） | `columns[{key,title,type,align}]`、`rows`、`page_size`、`title` |
| `callout` | 提示条 | `level`（info / success / warning / danger）、`title`、`text` |
| `item` | 左图右文的实体卡（商品、订单、人） | `title`、`image`、`eyebrow`、`meta[]`、`code`、`highlight`、`tags`、`link` |
| `timeline` | 时间线或进度 | `steps[{time,text,status}]`，status 为 done / current / warning / error / pending |
| `columns` | 2–3 栏并排 | `columns[[子块…]]`，子块为 `{"type":"markdown","text":…}` 或带 `type` 的 kpi / chart / callout / item / timeline / people / note |
| `people` | 人员展示（头像加名字，不发通知） | `users[]`（邮箱、登录名或姓名）、`title` |
| `note` | 口径、数据来源等脚注 | `text` |
| `actions` | 一排按钮，最多 6 个，文字不超过 40 字 | `buttons[{text,url,style}]`（跳转）或 `buttons[{text,"reply":true,style}]`（回复，见下文「交互」） |
| `raw` | 原生卡片组件（给技能作者精确控制） | `elements[]`（按字段白名单裁剪）、`fallback`（其他出口显示的文字） |

相邻两个带 `"size": "half"` 的 `chart`、`kpi` 或 `callout` 会自动并排成一行。

### 图表

`chart` 取 line、area、bar、hbar、pie、donut、funnel、combo、progress、ring、radar、scatter。数据三选一：

- `x` + `series[{name, values, kind, axis}]`：折线、面积、柱状、组合、雷达。
- `items[{name, value}]`：饼、环、漏斗、排行条形、进度条、环形进度。
- `points[{x, y, size, group}]`：散点。

可选：`format`（`unit`、`prefix`、`decimals`、`scale` 为 auto/wan/yi、`percent_input` 为 ratio/percent）、`labels`（auto/none/all/last/max）、`highlight`（last/max/类目名）、`stack`、`top_n`、`center`（环图中心文字）、`summary`（图下结论）、`size`（full/half）。

图表按模板生成 VChart spec：不写任何文字、坐标轴、网格、底轨的颜色，交给飞书的深浅主题；数值标签的颜色用主题语义色；数据色取在浅色、深色背景上都清楚的中明度色。

## 交互

### 回复按钮

`actions` 块里写 `{"text": "按品类统计", "reply": true}` 的按钮是回复按钮：提问人点一下，就等于他自己把按钮上的字作为下一句话发给 AI 员工，回答引用这张卡片。

- **所见即所发**：发出去的永远是按钮上看得见的文字（不超过 40 字），没有隐藏内容。`reply` 只是「这是回复按钮」的标记，写 `true` 或任意字符串都算；写成字符串时字符串的内容不会发出去。
- **只在提问人自己的对话回复里可点**：worker 开流时把这一轮提问人的飞书 `user_id` 写进流的上下文，网关编译终稿（含续卡）时写进按钮的回调 value。其余出口（定时任务结果、个人推送、发给其他接收人的通知等出站 Markdown）没有提问人，回复按钮只显示成灰字「「按钮文字」」，不带任何点击行为。
- **只有提问人能点**：群里别人点了，回调直接拒绝，toast「只有提问人可以选择」，不入队、不改卡片（与选择题卡片「别人点了不算」一致）。value 由渲染器生成，raw 块里的回调会被裁掉，模型伪造不了。
- **会话类型由服务端判定**：飞书的卡片回调不带会话类型，value 里也不写。应答回调时查点击人与本 AI 员工的私聊记录（`user_reached`，只由真实的私聊消息写入）：记录的私聊正是这个会话才按私聊，否则一律按群。点出来的轮次不写这份记录，所以点击永远不会把一个群变成「私聊」。
- **身份**：点击人按回调里的 `user_id` 解析（需要应用的「获取用户 user ID」权限，缺了这次点击直接丢弃）；`union_id` 与 `tenant_key` 一并带上，按与打字消息同样的规则核验。在已核验的私聊里点，和在那里打字一样可以用飞书个人授权的工具与个人定时任务；群里点不行。提醒（「提醒我……」）仍只认打字的私聊消息。
- **应答**：回调在 3 秒内返回，只做判定和入站落库。toast：入队「已收到」（之后 worker 仍可能拒绝，所以不说「已发送」）、这一行已经点过「已选过」、别人点「只有提问人可以选择」。选择题等其他卡片仍只回一个对勾。
- **去重**：入站去重键是「卡片消息 + 按钮行」：平台重推、连点或点同一行的另一个按钮都只算一次。
- **置灰**：点击通过了入站的各道关（机器人启用、白名单、身份、命令）、这一轮真正开始时，worker 在开流的事务里排一条出站；被拒的点击不改卡片。出站循环把这一行的回复按钮置灰（链接按钮不动），并在下面加一行灰字「已选择：按钮文字」，群里还写明是谁点的（人员标签只展示、不通知）。卡片是共享的，所有人看到的都一样。
  - 流式主卡是卡片实体：按消息 ID 找到投递记录，用 CardKit `batch_update` 局部更新，序号与这张卡之前的操作共用、严格递增。按钮只出现在终稿里，终稿之前已经关了流式，不会撞上「流式期间回调不能更新卡片」。
  - 续卡是普通卡片消息：出站记录里存着卡片 JSON，改好后整卡 PATCH，并把改过的卡存回出站记录。
  - 回复完成 1 小时以后，流式主卡的投递记录随流一起清理，拿不到卡片实体和序号：点击照常处理，只是不再置灰，去重仍然有效。
  - 飞书拒绝这次更新（字段不认、ID 冲突，例如重放时「已选择」那一行已经加过）时只记一笔 `feishu_reply_used_rejected`，不重试。

### 选择题按钮

AskUserQuestion 的单选题、选项（含末尾的「其他」）为 2–4 个时，卡片显示一排按钮，点一下就提交，不再需要「下拉框 + 提交」。每个按钮的回调 value 带着 `task_id`、`event_key`、题目 key 和选项 id，入站折成与表单提交相同的 `selected`，后面的选择流程（包括「只认提问人」）不变。按钮文字截到 40 字以内（限流切换卡的实例名不在选项里截断，完整名字在卡片正文里）。多选题或选项更多时仍用表单。企业微信不受影响。

### 人员

`people` 块和表格里 `type: "person"` 的列，按邮箱（不分大小写）、登录名、姓名的顺序把人解析成飞书 `user_id`：只认在职、有飞书身份的成员，引导账号不算；同一个姓名对应多个人时不解析。解析到的显示成头像加名字（`person_list`、表格人员列），不发通知；解析不到的按灰色文字显示。一条回复最多解析 200 个名字。

## 投递

- **流式阶段**：
  - 正文逐字出现，打字速度约 50 字/秒（每 40 毫秒 2 个字），跟得上模型的输出；
  - 块写完的那一刻，整块插进卡片（图表、表格、指标块等和最终效果一致）；正在写的块显示「📊 正在生成图表…」这类占位；
  - 两个半宽块凑齐后自动并排；
  - 标题栏要整卡更新才能改，所以流式期间不显示，收尾时出现。
  - 实现上，每次推送把正文算成一串单元，和卡片上记下的布局（`feishu_deliveries.layout`）比较：最后一段正文变长只调流式文本接口；有块写完或占位换成块，用一次 `batch_update` 删掉变化起点之后的旧组件、插入新组件。卡片和布局对不上时整卡重建，流式模式保持开启。
  - 思考面板内容没变就不推。同一个 AI 员工的平台调用间隔 0.125 秒（原来 0.3 秒），几个回复同时进行时每张卡大约 1 秒刷新一次。
  - 流式模式开启 10 分钟后飞书会自动关闭：到 9 分钟时主动续开，被关掉了就重新开启后重试，长回答全程保持打字效果（原来 9 分钟后改成每次整卡替换）。
  - 流式期间整卡体积超过约 26KB 或组件超过 170 个时暂停加长和插入；飞书拒收某次更新时也暂停增量、只更新思考面板。收尾时整卡替换成完整内容。
- **收尾**：
  1. 编译整条回复。编译时正文图片照旧上传并内嵌，另起一行保留「查看原图」链接；实体卡的图片也会上传。
  2. 关闭流式模式，同时写入消息列表的预览文案（第一句结论或标题栏）。
  3. 整卡替换成富卡片。
- **续卡**：一张卡放不下（30KB、200 个元素）时，其余内容作为续卡紧接着发出；表格组件每卡最多 5 个，图表最多 5 个，超出的降级成数据表。
- **回退**：
  - 飞书拒绝富卡片（`200220`、`10002`、`200860`、`300305` 等）时，原地换成只有 Markdown 的简化卡；
  - 流式卡片本身发不出去时，照旧改发普通消息。
- **出站队列**：定时任务结果等出站 Markdown 消息也优先发卡片，被拒再退回 post。飞书的定时任务结果不再按字节切分，由网关按卡片预算分卡，避免把一个块切成两半。

### 生成的图片

Codex 的生图工具把图片存在 Runtime 节点的 `$CODEX_HOME/generated_images/<会话 ID>/` 里，`codex exec --json` 也不输出这一步，所以以前用户只能看到一个服务器路径。现在：

- **Codex 驱动**（`runtime_daemon/drivers/cmd/relay-codex/images.go`）会把图片随 SSE 流带回来，放在 relay 扩展字段 `delta.images`（`name`、`mime_type`、`alt`、base64 的 `data`）里。图片有两种来源：
  - 回合结束时，取本会话目录里这一轮新生成的图片，附在正文末尾；
  - 正文里用 `![说明](相对路径)` 链接的本地图片，在原位置换成图片本身。
- **限制**：只读工作目录和本会话生图目录里的文件，按文件内容判断是否为图片，单张不超过 10MB，每轮最多 9 张。
- **Worker**：用机器人自己的飞书凭证调 `im/v1/images` 上传，换来 `img_key`，再把 `![说明](img_key)` 作为独立一段写回正文。流式卡片的 Markdown 会直接显示这张图；收尾编译时它变成原生图片组件，post 降级时变成 `img` 节点。定时任务的结果也这样处理。
- **失败处理**：上传失败时，正文里留一行「图片上传失败」。企业微信机器人暂不支持在回复里发图，只留一行说明。
- **提示词**：飞书机器人走 Codex 后端时，system prompt 会说明生成的图片会自动附上，不要贴本地路径。
- **部署**：需要升级 Runtime 节点（驱动有改动），不需要数据库迁移。

企业微信和管理台的聊天记录不渲染卡片：含块的回复在这两处显示为降级后的 Markdown，例如图表显示成数据表、指标块显示成列表、提示条显示成引用。

## 真机预览

每次调整视觉后，用预览命令把样例发给自己，在浅色和深色主题、PC 和手机上各看一次：

```sh
coreman feishu-cards preview --to <登录名> [--bot <AI 员工标识>] [--sample daily|item|repricing|logistics|inspection] [--file reply.md] [--stream] [--apply]
```

不加 `--apply` 只调 CardKit 建卡片实体做校验，不发消息。`--stream` 让第一张卡按线上流程先流式打字、再整卡替换。样例在 `coreman/core/feishu_cards/samples.py`。

预览里的 `people` 按线上同样的规则查库解析。回复按钮也会显示，提问人就是接收人：预览卡片发在接收人与这个 AI 员工的私聊里，点了就是真的以接收人的身份给它发了一句话。
